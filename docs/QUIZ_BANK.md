# 문제 은행 기획서 — 210문항 설계

> 상태: 설계 초안(문항 본문은 아직 없음, 샘플 25개만 수록). 교육 범위는 [CURRICULUM.md](CURRICULUM.md)가 기준이고 단원 id는 [curriculum-units.json](curriculum-units.json)의 `unitId`를 쓴다.
> 구역 구성은 [CONTENT_PLAN.md](CONTENT_PLAN.md) 2·9장, 글 최소 원칙은 [STORY.md](STORY.md) 2·10장을 따른다.
> 표기: ⚠ = 사실 확인 필요 / ❓ = 결정 필요.

---

## 0. 현재 상태와 목표

| 항목 | 현재(코드) | 목표 |
|---|---|---|
| 입장 시험 | `GQ` 28문항(단일 풀), `GQU`(단원 태그별 풀)는 **비어 있음** | 구역별 풀 14~21문항, `GQU` 채움 |
| 행성 퀴즈 | `PQ` 25문항(행성 이름 키) | 행성 80종 각 1문항 이상 연결 |
| 형식 | `[문제, 정답, 오답1, 오답2, 오답3, 해설]` 4지선다, 런타임 셔플, 합격 2/3 | **형식 유지**(변환기로 호환) |
| 규모 | 약 53 | **210** (30개 단원 × 7문항) |

- 난이도 비율은 CONTENT_PLAN 9장(기초 40 / 표준 40 / 심화 20)을 채택한다. CURRICULUM 5장의 권장(30/50/20)은 [추정]이라 우선하지 않는다. ❓ 바꾸려면 3장 표만 다시 계산한다.
- 기존 53문항은 폐기하지 않고 **재태깅 후 흡수**한다(8장). 신규 문항은 2022 개정 `통합과학1·2` 기준이다.

## 1. 문항 스키마 (TS 타입 초안)

```ts
// client/src/data/quiz-bank/types.ts (예정)
export type UnitId =            // curriculum-units.json 의 unitId 30개
  | 'sci1-1-1' | 'sci1-1-2' | 'sci1-1-3'
  | 'sci1-2-1' | 'sci1-2-2' | 'sci1-2-3' | 'sci1-2-4' | 'sci1-2-5' | 'sci1-2-6'
  | 'sci1-3-1' | 'sci1-3-2' | 'sci1-3-3' | 'sci1-3-4' | 'sci1-3-5' | 'sci1-3-6'
  | 'sci2-1-1' | 'sci2-1-2' | 'sci2-1-3' | 'sci2-1-4' | 'sci2-1-5'
  | 'sci2-2-1' | 'sci2-2-2' | 'sci2-2-3' | 'sci2-2-4' | 'sci2-2-5' | 'sci2-2-6'
  | 'sci2-3-1' | 'sci2-3-2' | 'sci2-3-3' | 'sci2-3-4';
export type Diff = 'basic' | 'standard' | 'advanced';          // 기초 / 표준 / 심화
export type Use  = 'gate' | 'planet' | 'heist' | 'review';       // 시험 / 행성 / 하이스트 / 복습

export interface QuizItem {
  id: string;                 // 'Z03-1.3.3-02' = 구역03 · 단원 sci1-3-3 · 2번째 (영구 불변)
  unitId: UnitId;             // 주 단원(1개). 출제 분포 계산 기준
  subUnits?: UnitId[];        // 보조 단원(있으면). 분포 계산에는 안 셈
  std?: string[];             // 성취기준 코드 ['10통과1-03-03'] — 없으면 검수 불가
  zone: number;               // 주 구역 1~12 (3장 배정표)
  alsoZones?: number[];       // 다른 구역 풀에도 넣을 때(예: 중력 개념 → 11)
  diff: Diff;
  stem: string;               // 문두. 목표 ≤40자, 상한 70자
  correct: string;            // 정답. 보기 목표 ≤16자, 상한 24자
  wrong: [string, string, string];   // 오답 3개(정답 위치는 런타임 셔플)
  why: string;                // 해설 정확히 1문장, 상한 70자
  misconception?: string;     // 오답이 노리는 오개념 (CURRICULUM 4장 항목 또는 자유 서술)
  planets?: string[];         // 연결 행성 id (행성 퀴즈 후보). 없으면 일반 문항
  use: Use[];                 // 기본 ['gate','planet']; 하이스트 전용이면 heist 만
  heist?: 'H1'|'H2'|'H3'|'H4'|'H5'|'H6';
  img?: { kind: 'spectrum' | 'graph' | 'diagram' | 'emoji'; spec: string }; // 그림 문제(전체의 10%+)
  flag?: '⚠' | '경계';        // ⚠ 사실 확인 필요 / 경계 = CURRICULUM 경계 소재(사용 제한)
  status: 'draft' | 'checked' | 'approved';   // 6장 검수 단계
  author?: string;            // 작성 에이전트 라벨(추적용)
}

// 기존 코드 호환: 현재 GQ/PQ 는 string[] 이므로 변환기를 둔다.
export const toRow = (q: QuizItem): string[] => [q.stem, q.correct, ...q.wrong, q.why];
```

- **정답 위치를 파일에 두지 않는다**(`correct` 별도 필드). 기존처럼 런타임 셔플하면 위치 편향이 생기지 않는다.
- 저장 위치(예정): `data/quiz-bank/z01.ts … z12.ts`(구역별) + `index.ts`가 `GQU`(단원 태그 → 행/rows), `PQ`(행성 → 행)를 파생한다. `GQU` 키는 `sectors.ts`의 `units` 태그(현재 '물질','태양계' 등 한글)이므로 **unitId ↔ 기존 태그 매핑표**가 필요하다 ⚠ (구현 단계 과제).
- `id`는 한 번 정하면 바꾸지 않는다(복습 기록이 id를 키로 쓴다).

## 2. 단원 → 구역 배정 (12개 구역 × 30개 단원)

원칙: **단원당 정확히 7문항**, 한 단원은 한 구역의 주 단원. 구역의 소재(CONTENT_PLAN 2장)에 가장 가까운 단원을 둔다. 구역 소재와 어긋나는 문항은 `planets`로 억지 연결하지 않고 일반 문항으로 둔다.

| # | 구역 | 단원(unitId) | 단원 수 | 문항 |
|---|---|---|---|---|
| Z01 | 내행성대 | sci1-1-1 · sci1-1-2 · sci1-3-1 | 3 | 21 |
| Z02 | 소행성대 | sci1-1-3 · sci1-2-5 · sci1-3-4 | 3 | 21 |
| Z03 | 목성계 | sci1-3-2 · sci1-3-3 · sci2-1-5 | 3 | 21 |
| Z04 | 거대 얼음 행성계 | sci1-2-3 · sci1-2-4 | 2 | 14 |
| Z05 | 카이퍼대 | sci2-1-1 · sci2-2-5 | 2 | 14 |
| Z06 | 적색왜성 마을 | sci2-2-1 · sci2-2-2 · sci2-2-3 | 3 | 21 |
| Z07 | 쌍성·거주후보 | sci1-3-5 · sci2-1-2 | 2 | 14 |
| Z08 | 뜨거운 목성들 | sci2-1-3 · sci2-1-4 | 2 | 14 |
| Z09 | 성운 | sci1-2-1 · sci2-2-4 | 2 | 14 |
| Z10 | 초신성 잔해·죽은 별 | sci1-2-2 · sci1-2-6 · sci1-3-6 | 3 | 21 |
| Z11 | 가르강튀아 | sci2-3-2 · sci2-3-3 (+ 중력 개념 `alsoZones`) | 2 | 14 |
| Z12 | 알파 센타우리·판도라 | sci2-2-6 · sci2-3-1 · sci2-3-4 | 3 | 21 |
| | **합계** | 30 | 30 | **210** |

- 계산: 3단원 구역 6개(Z01·02·03·06·10·12) = 18단원, 2단원 구역 6개 = 12단원 → 30단원 ✓. 21×6 + 14×6 = 126 + 84 = **210** ✓.
- **CONTENT_PLAN과 다른 점**: Z11은 계획상 "중력 개념"이 소재이나 `sci1-3-3`은 Z03이 주 단원이다. → `sci1-3-3` **심화 문항을 `alsoZones:[11]`로 지정**(문항 수 증가 없음). Z09·Z10의 별 소재도 같은 방식으로 `sci1-2-2`(Z10)를 Z09 풀에 `alsoZones:[9]`로 일부 공유할 수 있다.
- Z08 하이스트 H2(산화·상태 변화)는 Z08 `sci2-1-3` + Z03 `sci2-1-5`, H1(중력·궤도)은 Z03 `sci1-3-3`, H3(별의 일생)은 Z10 `sci1-2-2`, H4(중력 개념)은 `alsoZones` 문항, H5·H6(에너지)은 Z12 `sci2-2-6` + Z09 `sci2-2-4`·Z05 `sci2-2-5`에서 뽑는다(`use`에 'heist' 추가, 문항을 새로 쓰지 않음).

## 3. 구역 × 난이도 배분표 (합계 210)

기초(B) 84 / 표준(S) 84 / 심화(A) 42 = 40 / 40 / 20 %. 앞 구역은 기초 위주, 뒤 구역은 심화 증가.

| 구역 | 문항 | B | S | A | 비고 |
|---|---|---|---|---|---|
| Z01 내행성대 | 21 | 13 | 6 | 2 | 튜토리얼 구역 |
| Z02 소행성대 | 21 | 11 | 8 | 2 | |
| Z03 목성계 | 21 | 9 | 9 | 3 | 심화 중 일부 `alsoZones:[11]` |
| Z04 거대 얼음 | 14 | 7 | 5 | 2 | |
| Z05 카이퍼대 | 14 | 6 | 5 | 3 | |
| Z06 적색왜성 | 21 | 7 | 9 | 5 | |
| Z07 쌍성·거주후보 | 14 | 6 | 5 | 3 | |
| Z08 뜨거운 목성들 | 14 | 4 | 6 | 4 | H2 풀 |
| Z09 성운 | 14 | 4 | 6 | 4 | 그림(스펙트럼) 문항 집중 |
| Z10 초신성·죽은 별 | 21 | 7 | 9 | 5 | H3 풀 |
| Z11 가르강튀아 | 14 | 5 | 5 | 4 | + 중력 개념 심화 공유, H4 풀 |
| Z12 알파 센타우리 | 21 | 5 | 11 | 5 | H5·H6 풀 |
| **합계** | **210** | **84** | **84** | **42** | |

- 검산: B = 13+11+9+7+6+7+6+4+4+7+5+5 = 84, S = 6+8+9+5+5+9+5+6+6+9+5+11 = 84, A = 2+2+3+2+3+5+3+4+4+5+4+5 = 42 ✓.
- 단원 안 규칙: 각 단원 7문항에 **기초 ≥ 1, 표준 ≥ 1**. 심화는 구역 합계만 지키면 되며 단원별 0도 허용(단, 구역 내 심화가 있는 단원이 2개 이상일 것).
- **그림 문항** `img` 비율 ≥ 10 %(21문항 이상): Z09 스펙트럼 6, 그래프(중화 온도·개체 수·효율) 6, 도식(권역·먹이 사슬·결합 모형) 6, 이모지 배열 3. 그림이 없어도 풀리는 **텍스트 대체 문장**을 `stem`에 둔다(접근성).
- 행성 연결: 구역의 행성 수(7·6·6·7·6·8·7·7·6·8·6·7 = 81) 이상의 문항에 `planets`를 단다. Z10은 행성 8종에 문항 21개이므로 여유가 작다 → 행성 퀴즈는 일반 문항 재사용 허용.

## 4. 출제 원칙

### 4.1 무문자 게임용 짧은 글 (STORY 2·10장)
| 항목 | 목표 | 상한 |
|---|---|---|
| 문두 | 1문장 ≤ 40자 | 70자, 2문장 이내 |
| 보기 | 단어·구 ≤ 16자, **네 보기 길이를 비슷하게** | 24자 |
| 해설 | **정확히 1문장** | 70자 |
- 상황 설명은 우주 소재를 맥락으로만 쓰고, 소재를 몰라도 풀리게 쓴다. 합답(ㄱ,ㄴ)·"모두 정답"·이중 부정 금지(CURRICULUM 8.1).
- 정답이 가장 길거나 구체적이면 안 된다. 정답 위치는 런타임 균등 셔플.
- 수치·단위·지수는 본문과 해설을 같은 표기로. 천체 수치는 CURRICULUM 7.1 표 값만(출처 `NASA`) 쓴다.

### 4.2 오답 보기 설계
1. 오답 3개 중 **최소 1개는 CURRICULUM 4장의 오개념**(예: 에어백이 충격량을 줄인다, 달에서 질량이 준다, 온실효과 = 오존층 파괴).
2. 나머지는 ①비슷한 용어(핵융합↔핵분열, 산화↔환원) ②인과 방향 뒤집기 ③계산 실수 유도(10의 거듭제곱, 지름/반지름) ④같은 범주의 다른 항목 중에서.
3. 터무니없는 보기 금지. 그럴듯하되 **교육과정 범위 안에서 명백히 틀려야** 한다(대학 수준에서 참인 서술을 오답으로 두지 않는다).
4. 문항마다 `misconception`을 가능하면 기록 → 복습 NPC가 "자주 걸리는 오개념"을 모아 보여 줄 수 있다.

### 4.3 경계 밖 내용 금지 (CURRICULUM 2.3 · 6.1 · 8.4)
| 금지 | 허용 형태 |
|---|---|
| 센서 작동 원리, 산화수, 열화학 반응식·엔탈피, pH 계산 | 해당 없음(출제 금지) |
| 아레니우스 외 산·염기 정의, 중화의 온도·지시약색 외 변화 | 아레니우스 + 온도·BTB 색까지 |
| 결합 성질 비교 | **전기 전도성만** |
| 규산염·단백질·핵산의 구조식·화학식 | 기본 단위체 수준 |
| 반도체 접합 원리 | 불순물로 전도성 조절까지 |
| 태양 핵융합 계산 | 정성적("질량 일부가 에너지로") |
| 역학적 에너지 보존 단독, 적색 편이·허블 계산, 탈출 속도 공식, 블랙홀 시간 지연·상대론 | 금지. 블랙홀은 "중력이 매우 커서 빛도 빠져나오지 못한다" 사실 선택지까지 |
| 우주 초기 원소 질량비(75 %/25 %) 등 세부 수치 | 지양 [추정] |
- 진행 중인 연구(철 비, 유로파·엔셀라두스 바다, 외계 생명 징후)는 정답 근거로 쓰지 않는다. 소재일 때도 "관측으로 시사된다" 수준 + `flag:'⚠'`.
- 인명·연도 암기, 교과서·문제집 문장 복사, 정치적 쟁점(에너지 정책 찬반) 금지.
- 윤리·SSI(`sci2-3-4`)는 **정답이 가치 중립적으로 판정되는 문항**만(책임·개인 정보 보호·안전 등). 찬반이 갈리는 주제는 출제 금지.

## 6. 시험(문)·복습·오답 재출제 규칙

### 6.1 시험(문) 3문항 구성 — 합격 2/3 (현행 유지)
1. 풀: 해당 구역 단원의 문항 + `alsoZones`에 그 구역이 있는 문항(Z11의 중력 개념 포함). 풀이 3문항 미만이면 지금처럼 `GQ`로 대체(구현 폴백 유지).
2. **난이도 구성**(3문항): Z01~Z02 = B·B·S / Z03~Z05 = B·S·S / Z06~Z12 = S·S·A. 심화가 모자라는 구역(Z01·02·04 등 A=2)은 상위 난이도로 채우지 않고 같은 난이도를 쓴다.
3. 3문항은 **서로 다른 단원**에서 뽑고(가능할 때), 같은 시험 안에 `misconception`이 같은 문항을 중복하지 않는다. `use`에 'gate' 포함 문항만.
4. 최근 6개 시험·행성 퀴즈에 나온 id는 제외(풀이 소진될 때만 허용). 보기 순서는 매번 새로 셔플.
5. 실패: 15초 대기(행성 퀴즈의 기존 `cd=15`와 통일) 후 **새 3문항**. 틀린 문항은 7장 복습 기록에 등록.
6. 정답/오답 직후 정답과 해설 1문장을 보여 준다(해설 노출 시간 고정, 스킵 가능).

### 6.2 행성 퀴즈 (1문항, 정답 시 훔치기)
- `planets`에 그 행성 id가 있는 문항 우선 → 없으면 그 구역 풀의 일반 문항. 80종 각각 최소 1문항을 `planets`로 보장.
- 구역 난이도 가중: Z01~Z03 기초 70 %, Z04~Z08 표준 중심, Z09~ 심화 25 % (정확한 확률은 밸런싱 에이전트가 정함 ❓).
- 오답 시 15초 쿨다운 후 같은 둥지에 재도전(현행). 재도전 문항은 **다른 문항**으로 바꾼다.

### 6.3 복습 NPC — 교수 "케플러" (CONTENT_PLAN 6장)
- 틀린 문항을 모아 둔 목록(`S.review`)에서 최대 5문항을 낸다. 한 번에 모든 오답을 쏟지 않는다.
- 박스 규칙(간단한 간격 복습): 오답 등록 `box=0` → 복습에서 정답이면 `box+1`, 오답이면 `box=0`. **`box=2`(서로 다른 두 복습에서 연속 정답)면 졸업**(목록에서 제거).
- 보상: 정답 1개당 소액 금화(구역 가중), 5문항 전부 정답이면 보너스(별조각 후보 ❓). 업적 "오답 복습 20회"와 연동.
- 정답이어도 해설 1문장을 다시 보여 준다. 오답 보기의 `misconception`이 있으면 아이콘 한 개로만 표시(글 최소).

### 6.4 오답 재출제 규칙 (게임 중)
- 오답은 `S.review[id] = {miss, box, last}`로 기록한다. **기존 `S.notes`는 위험 구역 안내용 `Record<string, number>`라 충돌하므로 새 필드가 필요**하다 ⚠(`core/types.ts`, `save-schema.ts` 버전업은 구현 단계).
- 행성 퀴즈·시험을 만들 때 해당 구역(또는 이전 구역)의 복습 목록이 있으면 **약 25 % 확률로 복습 문항을 1개 섞는다**(시험에서는 3문항 중 최대 1개, 합격 판정에는 포함).
- 같은 id는 복습 외에 연속 두 번 나오지 않는다. 졸업한 문항도 일반 풀에는 남는다.
- 세이브 용량: 목록 상한 60개(초과 시 `box` 높은 순 제거).

## 8. 검수 체크리스트

각 문항은 작성자 → 교차 검수자(다른 에이전트) → 최종 확인 순으로 `draft → checked → approved`.

**A. 교육과정**
- [ ] `unitId`·`std`가 맞고 **한 문항 = 한 판단**이다.
- [ ] CURRICULUM 2.3의 "다루지 않는 범위"·6.1 경계 소재를 쓰지 않았다(4.3 표).
- [ ] 정답 판정에 교육과정 밖 지식이 필요하지 않다.
- [ ] 난이도 정의(5장): 기초=단일 개념, 표준=2개 연결·자료·간단 계산, 심화=통합 추론.

**B. 과학 사실**
- [ ] 정답이 **하나**이며 오답은 모두 명백히 틀리다(교육과정 밖에서 참인 오답 없음).
- [ ] 수치·단위 재계산(10의 거듭제곱, 지름/반지름, km/m). 천체 수치는 CURRICULUM 7.1 표와 일치.
- [ ] 진행 중 연구·가설은 "가설/시사" 표현, 확인 못 한 것은 `flag:'⚠'`로 남기고 `approved` 금지.
- [ ] 이중 부정·"항상/모든/반드시" 같은 절대 표현으로 정답이 갈리지 않는다.

**C. 글 최소·형식**
- [ ] 문두 ≤ 70자(목표 40), 보기 ≤ 24자(목표 16)이고 네 보기 길이·문체가 비슷하다.
- [ ] 해설이 **1문장**이다. 근거 중심, 오개념은 짧게.
- [ ] 합답·"모두 정답"·"정답 없음" 없음. 그림 문항은 텍스트 대체 문장이 있다.
- [ ] 교과서·문제집 문장 복사 아님(자체 서술).

**D. 데이터 무결성**
- [ ] `id` 형식과 유일성, `correct`가 `wrong`과 같지 않음, `wrong` 3개가 서로 다름.
- [ ] 구역·단원·난이도 개수가 2·3장 표와 일치(자동 스크립트로 검증: 구역별/난이도별 집계, 단원당 7개, 그림 비율, 행성 연결 수).
- [ ] 중복 의심 문항(같은 정답·같은 개념) 없음. 동일 단원 내 `misconception` 편중 ≤ 3.

**E. 정리 단계(전체)**
- [ ] 정답 위치는 파일에 없으므로 편향 검사는 셔플 결과 1,000회 시뮬로 확인.
- [ ] 30개 단원 모두 기초·표준 포함, 80개 행성 모두 `planets` 연결 ≥ 1.
- [ ] 기존 53문항 이관 완료 및 경계 소재 문항 교체.

## 9. 작성 워크플로 (에이전트 병렬 분담안)

1. **준비(직렬, 1명)**: `types.ts`, id 규칙, 집계 검증 스크립트, 단원 태그 ↔ `GQU` 키 매핑표를 먼저 만든다. 모든 작성 에이전트에 CURRICULUM 2.3·4·7장과 이 문서 4장을 필수 입력으로 준다.
2. **작성(병렬, 6명)** — 각자 2개 구역(= 28~42문항), 파일 `z{NN}.ts` 단위라 **충돌 없음**:

3. **교차 검수(병렬, 3명)**: 작성자와 **다른** 에이전트가 8장 체크리스트 A~D 수행. 담당은 R1 = Z01~Z04, R2 = Z05~Z08, R3 = Z09~Z12. 결과는 문항별 `checked`/수정 사유(`flag`)로 남긴다.
