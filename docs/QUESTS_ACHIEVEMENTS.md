## 2. 아이콘 의뢰 30개

### 2.1 규칙
- **요구 시퀀스**는 화면에 아이콘 줄로만 표시(예: 🌍→📦→🌙). `→`는 순서, `+`는 동시 조건.
- 아이콘 의미(의뢰판 공통 범례): 📦 배달, 🪐 행성 훔치기, 📷 관측(이미지 퀴즈), ☄️ 추격, 🔧 수리, 🧪 샘플, ❓ 퀴즈, ⏱️ 시간제.
- 보상: 💰 금화(UX 10.3의 통화 아이콘과 동일. 구역 평균 행성 가격 대비 %, 최종값은 `data/pacing.ts`), ⭐ 별조각, 🎁 아이템/장식. 금화는 “평균 가격의 20~60%”를 기준으로 시작한다.
- 교육 연결은 CURRICULUM 단원 id(없으면 주제어). **관측형은 이미지 문제를 우선**(STORY 10장).
- 수락 후 포기 가능, 재수락 가능. 진행도는 `S.quests`에 저장(5장).

## 5. 세이브 필드·데이터 스키마 초안

현행 세이브는 v5(`stealPlanet4` 키, `ver: 5`)이며 `quests, vehicles, heists, collectibles`가 **빈 기본값**으로 이미 있다(ROADMAP). 스토리는 v6에서 `S.story`를 추가할 예정(STORY 7.1)이므로, 이 문서의 필드는 **v6에 함께 넣는 것을 권장**한다(마이그레이션 1회). 체인은 `client/src/core/save-schema.ts`에 추가.

// ⚠ 현행 v5 SaveState: quests/ach/coins/vehicles/heists: Record<string, number>, collectibles: Record<string, 1>, playSec: number.

//   (migrate() 의 "없는 필드만 defaults 로 채움" 규칙은 v5 의 빈 `{}` 를 그대로 두어 `S.quests.active` 가 undefined 가 된다).
export interface SaveV6 {
  ver: 6;
  // ...기존 v5 필드 유지...
  story: { beat: number; mid: number; seen: Record<string, 0 | 1>; ended?: 0 | 1; hints?: Record<string, 0 | 1> }; // STORY 7.1 + UX_CUTSCENE 2·5장(mid 는 beat===4 일 때 0~5 = 4-1~4-5, 진행 비교값 beat + mid/10)

  quests: {
    active: Record<string, { step: number; progress: number; startedAt: number }>;

  };

  races: Record<string, { bestMs: number; medal: 0 | 1 | 2 | 3; vehicle: string }>;

  ach: {
    got: Record<string, number>;                 // 업적 id -> 달성 playSec
    equippedTitle: string | null;                // 머리 위에 표시할 칭호 이모지 1개

      disguiseSpotted: number;
      warpUses: number;
      wandererQuests: number;

    wandererSector: string;                      // N14 현재 위치(섹터 id)

- **마이그레이션**: `STEPS[5]` 에서 v5 의 빈 맵을 새 모양으로 **교체**한다 — `quests = {active:{},done:{},failed:{}}`, `collectibles = {stars:{}, starsSpent:0}`(v5 `collectibles` 는 `Record<string, 1>` 빈 맵), `races = {}`, `ach = {got:{}, equippedTitle:null, counters:{...0}}`, `npc = {spoke:{}, wandererSector:…, wandererDay:0, reviewDaily:{day:0, n:0}}`, `review = {}`, `story = {beat:0, mid:0, seen:{}}`. 단, v5 에서 이 필드에 이미 값이 들어 있는 세이브(개발 중 수동 주입 등)가 있으면 `typeof v === 'object' && !Array.isArray(v) && 'active' in v` 로 모양을 검사해 보존한다. 기존 `S.mi`(미션 진행)는 유지하고, 도감·`S.stolen`으로 일부 업적(A09, A17)을 **소급 달성**시킨다.
- 업적 달성 판정은 미션처럼 매 프레임이 아니라 **이벤트 훅**(훔침·퀴즈·획득 시)에서만 `checkAch()`를 부른다(성능).
- 세이브 용량: 최악(업적 50·의뢰 30 완료·레이스 12·복습 60·집 4 모두 채움) 직접 직렬화하면 v6 신규 필드가 **약 8KB**(QUESTS 계열 ≈5KB + `review` 60개 ≈2.7KB), 전체 세이브 약 12KB 로 서버 PUT 상한 256KB 의 약 5% 다. 클라이언트 `queueRemoteSave` 는 상한을 `json.length`(UTF-16 코드 단위)로 재고 서버는 본문 **바이트**(`req.body.size()`)로 재므로 한글·이모지 문자열이 늘면 둘이 어긋난다 — 칭호 이모지 외에는 id·숫자만 저장하는 현재 규칙을 유지한다. 서버(`handlers.cpp`)는 본문이 JSON 객체이고 ≤256KB 이면 필드 구성을 검사하지 않고 저장하므로 새 필드가 거부될 일은 없다.
