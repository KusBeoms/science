**데이터 포맷 실제값 (2장과 다른 점)**
- 모든 `Vec3` 는 **재생 시작 시 플레이어 위치 기준 상대 좌표**(회전 없음). 'player' 배우는 실제 `G.me` 를 빌려 구동하고 종료 시 위치·방향·포즈를 복구한다(입력 잠금 컷신에서만 위치·방향을 움직임).
- 키 공통: `t`, `ease`, `cut:true`(직전 키에서 보간 없이 그 시각에 점프 — 컷 직전에 `t-0.01` 키를 하나 둬서 앞 컷을 끝낸다). 필드를 가진 키끼리만 보간하고 첫 키 이전은 첫 값 유지. 트랙은 로드 시 시각순 정렬.
- `setup` 은 `{actors}` 만(`time`·`weather`·`endState`·`SkipSnapshot` 제거 — 날씨는 FX `rain`, 상태 변경은 `onEnd` 하나로 통일). 배우 kind 11종 전부 구현(placeholder 형상: `apple ring coin line sprout knife triple` 은 기본 도형 — **`ring`·`sprout` 는 사용자 결정(결계·🌱 삭제)으로 더는 쓰지 않는다. 구현 정리 시 제거**, `guard`=`makeGuardian`, `npc/silhouette`=`blocky`).
- 트랙에 `{type:'ui', kf:[{t, hud:boolean}]}` 추가: 게임플레이 HUD 숨김(`body.cine-nohud`). 기본은 입력 잠금 컷신 숨김·오버레이 표시.
- `EndEffect` 에 `{do:'ended'}`(→`S.story.ended=1`) 추가. 디렉터가 직접 처리: `beat`(mid=0 리셋) `mid`(beat===4 일 때만) `flag`(`seen[key]`) `ended` `save`. 나머지(`gaugeSync flushNotices start unlock`)는 `G.cineHooks.effect(e)` 로 위임. `seen[id]=1` 은 `onEnd` 와 함께 **항상**(재시청 제외) 기록.
- FX `amt`/`dur`: `fade dim vignetteRed rain` = 목표 불투명도 램프 · `flash` = 순간 밝기(상한 0.25, 모션 감소 시 생략) · `shake` = 카메라 진폭 · `slowmo` = 컷신 시간 배속 · `sparkle` = `at` 배우 위치 ✨ · `spot` = `at`(배우 id 또는 HUD 대상 `apple|wanted|dir`) 스포트라이트.
- 훅: `G.cineHooks.sound(cue,{vol,pan,duck})` · `hud(HudKey|null)`(null = 컷신 종료, 미리보기 원복) · `effect(EndEffect)`. 전부 optional — 구현하는 모듈이 대입한다.
- 일시정지: 입력 잠금 컷신은 `paused()` true(`G.cine.lock`), 오버레이는 퀴즈·도감·상점·모달이 열린 동안 `cineT` 정지. 입력 잠금 컷신이 오면 재생 중 오버레이는 즉시 종료 처리, 대기열은 1개.
- 건너뛰기: 0.3초 페이드 후 `onEnd` 실행(정상 종료와 동일). 정상 종료 시 컷신 카메라→조작 카메라로 0.8초 보간 복귀. 오버레이의 ⏭ 는 44px 칩(화면 우중), Space 는 점프이므로 Enter/Esc 만.

**`iconToast` / `HudWidget` (`game/hud.ts`)**
- `iconToast(icons: IconKey[], sec=1.2)`: 화면 중앙 하단 위 `#itoast`, 이모지+shape 외곽만(숫자 `×n` 허용), 큐 최대 2·같은 아이콘 연속은 `×n` 합침, 컷신·오버레이 중엔 보류(최대 2) → 종료 시 `flushIconToasts`. **규칙: 스토리·튜토리얼·알림 경로는 `iconToast` 만, 문장 `toast()` 는 시스템 오류 전용**(E2E 가 `data/cutscenes.ts`·`game/cutscene*.ts`·`systems/cutscene.ts` 의 `toast(` 와 한글 리터럴 0건을 검사).
- `HudWidget{id, slot:'TL'|'TC'|'TR'|'L1'|'L2'|'RM', priority, icons[], fill?}`: `addHudWidget(() => HudWidget|null)` 또는 `GameSystem.widget()`. 슬롯 상한 `{TL:2,TC:1,TR:2,L1:1,L2:1,RM:1}` · 총량 6 · 초과 시 priority 낮은 것부터 숨김을 `renderHudWidgets()`(=`renderHudLines()` 끝에서 호출)가 강제. 슬롯 좌표는 임시(`cine.css`), HUD 슬롯 격자(10.3) 도입 시 재배치.

**세이브 v6 `S.story`** (`core/types.ts` `StoryState`, `core/save-schema.ts`): `{beat:0, mid:0, seen:{17키:0}, ended:0, hints:{}}`, `SAVE_VER=6`. `STEPS[5]` 는 story 만 만든다(기존 v5 의 다른 빈 필드는 건드리지 않음). 이미 진행한 v5 세이브(`stolen·zone·bought·cr>10`)는 `seen.c01_love=1, beat=1` 로 시작해 C01 이 재생되지 않는다. `beat!==4` 면 `mid=0` 보정. 상위 버전 세이브는 STEPS 를 건너뛰고 `ver` 도 낮추지 않는다(story 가 있으면 그대로 보존).

**E2E**: `client/tests/e2e/cutscene.spec.ts` 9건 — C01 전체 재생(텍스트 노드 0·`beat=1`·카메라 복귀)·⏭/Space 건너뛰기·키 비누수·오버레이 입력 비차단·`iconToast`(병합/큐/보류)·`HudWidget` 상한·세이브 v6(마이그레이션/상위 버전 보존)·규칙 린트. 다른 E2E 가 C01(20초 입력 잠금)에 막히지 않도록 `fixtures.ts` 의 `open()` 은 기본 `?cine=0` 을 붙인다(컷신 테스트만 `?cine=1`).

## 2. 컷신 디렉터 데이터 포맷 (TS 초안)

STORY 7.1을 확장. **텍스트 필드 없음**(`bubble.text` 같은 필드는 타입에 존재하지 않는다). 파일: `game/cutscene.ts`(런타임), `data/cutscenes.ts`(데이터). 컷신 12개와 **중간 비트 오버레이 5개(1.1절)가 같은 `CutDef`** 를 쓴다(`mid` 필드로 구분).

```ts
export type CutId = 'c01_love' | 'c02_gauge' | 'c03_caught' | 'c04_hide'
  | 'c05_triple' | 'c06_chase' | 'c07_safe' | 'c08_rich' | 'c09_go'
  | 'c10_quest' | 'c11_knife' | 'c12_free'
  // 중간 비트 4-1~4-5 (STORY 4.1) — 같은 CutDef, mid 1~5
  | 'm4_1_reach' | 'm4_2_rocks' | 'm4_3_shadow' | 'm4_4_hide' | 'm4_5_far';

export type Vec3 = [number, number, number];
export type Ease = 'linear' | 'in' | 'out' | 'inOut' | 'back';

/** 감정/사물 아이콘 키 (3장 사전의 key). 문자열 리터럴 유니온으로 오타를 컴파일 때 잡는다 */
export type IconKey = keyof typeof ICONS;

export interface CutDef {
  id: CutId;
  beat: number;                 // STORY 비트 번호 (1~12). 중간 비트는 4
  mid?: 1|2|3|4|5;              // 중간 비트 4-n이면 n (beat===4일 때만). 컷신 12개는 생략
  durSec: number;               // 컷신 5~25, 중간 비트 7~10
  skippable: true;
  skipHold?: number;            // 길게 누르기 확인(초). C11만 1.0
  letterbox?: boolean;          // 중간 비트는 false
  lockInput?: boolean;          // false = C02, C04, 중간 비트 전부(플레이 유지)
  setup?: Setup;                // 시작 전 월드 배치 (배우 스폰, 시간대, 날씨)
  tracks: Track[];              // 아래 키프레임들 (시간순 정렬 불필요, 로드 시 정렬)
  onEnd: EndEffect[];           // 건너뛰기 시에도 반드시 실행
  endState?: Partial<SkipSnapshot>; // 건너뛰기 시 즉시 적용할 최종 상태
}

export interface Setup {
  actors: { id: string; kind: 'player'|'apple'|'guard'|'npc'|'knife'|'triple'|'silhouette'|'coin'
    |'ring'    // (폐기: 금화 고리 결계 삭제 — 구현 정리 시 제거)
    |'line'    // 거래의 선 — 바닥 금빛 선(C03·C07)
    |'sprout'  // (폐기: 🌱 연출 삭제 — 구현 정리 시 제거)
    ; pos: Vec3; yaw?: number }[];
  time?: number;                // 0~1 낮밤
  weather?: 'clear'|'rain';
}

export type Track =
  | { type: 'camera'; kf: CamKey[] }
  | { type: 'actor'; id: string; kf: ActKey[] }
  | { type: 'bubble'; kf: BubbleKey[] }
  | { type: 'fx'; kf: FxKey[] }
  | { type: 'sound'; kf: SndKey[] }
  | { type: 'hud'; kf: HudKey[] };

export interface CamKey { t: number; to: Vec3; look: Vec3; fov?: number; ease?: Ease; cut?: boolean; shake?: number;
  soft?: boolean }              // true: 플레이어 카메라 위에 얹는 시선 보조(≤0.6s), 시점 입력 시 즉시 해제. lockInput:false 오버레이 전용(재시청 모드에선 무시하고 고정 카메라)
export interface ActKey { t: number; pos?: Vec3; yaw?: number; scale?: number; anim?: 'idle'|'walk'|'run'|'grab'|'cheer'|'shock'|'melt'|'hide'; ease?: Ease; visible?: boolean; follow?: string }
export interface BubbleKey { t: number; who: string; icons: IconKey[]; dur: number; pop?: 'pop'|'shake'|'pulse' } // icons: 1~3개
export interface FxKey { t: number; kind: 'vignetteRed'|'rain'|'sparkle'|'shake'|'fade'|'flash'|'spot'|'slowmo'|'dim'; amt?: number; dur?: number; at?: string }
export interface SndKey { t: number; cue: SoundCue; vol?: number; pan?: number; duck?: boolean }
export interface HudKey { t: number; target: 'apple'|'wanted'|'dir'; set?: number; spotlight?: boolean;
  from?: 'cur' | number;        // 'cur'=연출 시작 시점의 실제 값. C05 미리보기 현재→100%, C08 60%→100%
  preview?: boolean }           // true면 표시만 보간하고 실제 값(S.earned)은 불변, 종료 시 원복

export type SoundCue = 'heart'|'coin'|'sting'|'drone'|'quake'|'roar'|'door'|'portal'|'fanfare'|'knife_hit'
  | 'knife_spin'|'glass_crack'|'rain'|'silence'|'bgm_explore'|'bgm_chase'|'bgm_happy'|'bgm_off';

export type EndEffect =
  | { do: 'beat'; to: number }              // beat를 올리면 mid는 0으로 리셋(beat===4가 아니면 mid=0)
  | { do: 'mid'; to: 1|2|3|4|5 }            // 중간 비트: S.story.mid 설정 (beat===4일 때만 유효)
  | { do: 'flag'; key: string; v: 0|1 }
  | { do: 'gaugeSync' }                     // 게이지는 파생값(누적 번 금화÷사과 가격)이라 값을 쓰지 않고 표시만 실제 값에 맞춤
  | { do: 'flushNotices' }                  // C12 종료: 연출 보호 구간 중 보류한 알림 일괄 표시(5.4절)
  | { do: 'start'; sys: 'watcher'|'chase' }
  | { do: 'unlock'; what: 'house'|'request' }
  | { do: 'save' };

export interface SkipSnapshot { camera: 'gameplay'; weather: 'clear'|'rain'; bgm: SoundCue }
```
핵심 규칙
1. **시간 기준은 `G.gameT`가 아닌 컷신 전용 `cineT`**(일시정지·탭 이탈 시 정지). 키 사이는 `ease` 보간, `cut:true`는 보간 없이 점프.
2. `play(id)` → `G.cine = {def, t:0}`; `paused()`는 `G.cine && def.lockInput !== false`일 때 true. 월드 시뮬은 멈추고 렌더·사운드·말풍선만 돈다.
3. `skip()`은 (a) `endState` 적용, (b) 모든 `onEnd` 실행, (c) 0.3초 페이드. **게임 상태 변경은 `onEnd`에만** 둔다(재생 중 변경 금지) → 건너뛰기와 정상 종료의 결과가 동일.
4. 세이브(**STORY 7.1과 동일**, `core/save-schema.ts` v6):
   ```ts
   S.story = {
     beat: number;                      // 1~12
     mid: 0|1|2|3|4|5;                  // beat===4일 때만 1~5(4-1~4-5), 그 외 0. 진행 비교값 = beat + mid/10
     seen: Record<CutId, 0|1>;          // 컷 id → 0|1 (컷신 12 + 중간 비트 5 = 17키; 마이그레이션 시 없는 키는 0)
     ended?: 0|1;
     hints?: Record<string, 0|1>;       // 튜토리얼 힌트 key → 영구 비표시(5.1)
   }
   ```
   `seen`이 0이면 건너뛰기 버튼을 2초 지연 표시, 1이면 즉시. (초안의 `ended=true` 표기는 `1`로 통일.)
5. 말풍선은 DOM(`#cine .bub`) — 월드 위치 투영, 최대 동시 3개, 아이콘은 이모지+`data-shape` 속성(3.3)으로 외곽선 도형 병기.
6. `lockInput:false` 컷(C02·C04·중간 비트)은 `G.cine`을 점유하되 `paused()`를 올리지 않는다. 컷신(`lockInput` 기본)이 요청되면 재생 중 오버레이는 즉시 종료 처리(`onEnd` 실행)하고, 오버레이끼리는 큐(선입선출 1개). `S.story.mid`/`seen`은 `onEnd`에서만 갱신.

## 3. 이모지/아이콘 사전
### 3.1 설계 규칙
- **한 말풍선 = 이모지 1~3개**, 3개 초과 금지. 모든 의미는 **이모지 + 외곽 모양 + (선택)소리**의 3중 병기.
- 이모지 렌더링은 OS마다 다르므로 `ICONS[key] = {emoji, shape, svg?}`로 추상화. 1차는 이모지, 2차(품질 단계)에 핵심 12개(💗💰❗⚠️👁️🍎🗡️😢🎒🏠⏭✅)만 자체 SVG 스프라이트로 교체(추천값, 9장 #3). `svg`가 있으면 우선, 나머지는 이모지 유지.
- 말풍선 외곽 모양 `shape`(색이 아닌 **형태**로 의미 구분): 
  - `round` 둥근 구름 = 감정/생각, `spike` 톱니 = 위험/경고, `square` 각진 사각 = 의뢰/지시, `hex` 육각 = 상태/시스템.

| 안내 | hint_hand | 👆 | round | 튜토리얼 |
| 안내 | hint_look | 👀 | round | 시선 |
### 3.3 모양 병행 접근성 구현
- DOM: `<span class="ic ic-spike" data-shape="spike" role="img" aria-label="{lang.key}">⚠️</span>` — `aria-label`은 **스크린리더 전용**이고 시각 텍스트가 아니므로 무문자 규칙에 위배되지 않는다(확정: 허용, 단 **한 단어**로 제한 — 9장 #4).
- 같은 이모지가 의미 둘로 쓰이지 않게 한다(💰=돈 하나만, 🪙 불필요).
- 위험(spike)은 **테두리 점선 + 가장자리 진동(모션 감소 시 진동 정지, 점선만 유지)**.

## 5. 튜토리얼 (무문자)
### 5.1 방식
- **상황 트리거 힌트**: 처음 해당 상황이 되면 1회, 대상 근처에 **손가락/키 아이콘 + 대상 하이라이트**를 띄운다. 행동 성공 시 ✅ 팝 후 사라짐. `S.story.hints[key]=1`로 영구 비표시. 성공 전에는 10초 후 재표시(최대 3회).
- 힌트는 **전부 `HintDef` 데이터**: `{key, when(state), anchor(target), icons[], loop: 'tap'|'drag'|'hold'|'pulse'}`. 문자열 필드 없음.
- 키 아이콘은 입력 장치에 따라 교체(데스크톱: ⌨️ 키캡 모양 `W A S D`/`E`/`F`/`Shift`/`Space`는 **글자 키캡 허용**—기기 표면 표기이므로 문장이 아님. 터치: 손가락 👆 + 조이스틱 궤적).
### 5.2 힌트 목록 (상황별)
| key | 트리거 | 표시 | 성공 조건 |
|---|---|---|---|
| move | 첫 조작 가능 직후 3초 무입력 | 조이스틱/WASD 키캡에서 화살표 방향 4개 순환 + 바닥 발자국 `👣` | 3m 이동 |
| look | 이동 성공 후 | 화면 중앙 `👀`과 좌우 화살표 곡선 | 시점 45° 회전 |
| approach | 첫 둥지 20m 이내 | 행성 위 ⬇️ + 바닥 링 | 4m 이내 |
| grab | 둥지 근접(E 가능) | `[E]` 키캡 + 행성 + 🎒 (E 두드림 애니메이션) | 줍기 |
| quiz | 퀴즈 첫 오픈 | 보기 4개 중 하나를 👆가 가리킴(첫 1회만, 정답 비누설) → **문장 없음**, 타이머 모양 ⏳만 | 보기 선택 |
| run | 스태미나 풀 + 이동 중 | `Shift`/🏃 점멸, 스태미나 바 ⚡ 강조 | 달리기 1초 |
| tired | 스태미나 바닥 | 바 빨강 + 💤 | 회복 |
| carry_back | 가방 가득/둥지 처리 후 | 기지 방향 호 + 🏠 + 🎒→🏠 점선 화살표 | 기지 도착 |
| deposit | 기지 슬롯 앞 | 슬롯 하이라이트 + `[E]` 🎒⬇️ | 입고 |
| sell | 암시장 상인 근처(C02) | `[F]` + 행성→💰 | 판매 |
| shop | 첫 돈 충분 | 🛒 버튼 맥동 + 👆 | 상점 오픈 |
| watch | C03 이후 첫 수호신 시야 진입 | 👁️ 점멸 + 화면 가장자리 | 시선 돌려서 숨김 확인 |
| caught | 첫 `caught()` | 💸 낙하 + 🏠 복귀 화살표 | — |
### 5.3 공통 규칙
- 한 번에 힌트 1개만. 우선순위: 생존(`caught`/`watch`) > 진행 > 편의.
- 컷신 중·퀴즈 중 비표시. 모션 감소 시 애니메이션 대신 **정적 아이콘 + 2Hz 이내 깜빡임**.
- "다시 보기" 버튼: 설정 메뉴에 💡 아이콘(힌트 초기화; 10.1·10.7에서 ❓→💡로 변경, ❓=퀴즈 전용).
- 중간 비트 오버레이(1.1) 재생 중에는 힌트를 대기시키고 종료 후 재개. M4-3 직후의 은신 힌트처럼 오버레이 → 힌트 순서가 겹치면 오버레이가 우선.

### 5.4 연출 보호 구간 알림 억제 (STORY 7.5)
**보호 구간 = 비트 5(C05 시작)부터 C12 종료까지.** 판정: `protect = (S.story.beat >= 5 || C05 재생 중) && !S.story.seen.c12_free` (C12를 건너뛰어도 `seen`이 1이 되므로 해제).
| 대상 | 보호 구간 중 | 해제 시 |
|---|---|---|
| 일반 의뢰 알림(새 의뢰 도착·❗n 배지 갱신 토스트) | `iconToast` 보류(큐 저장) | `flushNotices`: C12 종료 직후 한꺼번에 |
| 업적 토스트 | 보류 | 동일 |
| 방랑 수집가(N14) 팝업 | 보류(스폰 자체 억제) | 동일 |
| 하루 1회 보너스 알림 | 보류 | 동일 |
| 업적의 시간 기준(예: 10시간 플레이) 판정 | 판정 유예 | C12 종료 후 판정 |
| 비트 7~8 사이 라이벌 기지 침입 이벤트 | 억제(확보한 삼성 보호) | 비트 8 이후 평상 |
| 시간제 의뢰 타이머 | 비트 6(추격)에서 일시정지 | 추격 종료(비트 7) 후 재개 |
- **표시 방식**: 보류분은 개별 토스트로 쏟아내지 않는다. `☰` 허브 타일에 **새 소식 점(●)** 을 켜고(10.5), 요약 `iconToast` **1개**(아이콘 ≤3, 예: 🏆❗💰)만 10.9의 토스트 규칙(큐 최대 2개)대로 띄운다. 보류 큐는 세이브 대상 아님(로드 시 `seen`·진행도에서 재계산).
- **억제하지 않는 것**: 생존 정보(TC 주의 슬롯의 추격 ⚠·수배 눈꺼풀, 방향 화살표 — 10.3), 시스템 오류 `toast()`(저장 실패), 퀴즈·상점·도감 같은 플레이어가 연 화면. 이들은 알림이 아니라 상태/요청 응답이다.
- 컷신·오버레이 중 `iconToast`/힌트 대기(5.3)는 보호 구간과 별개로 항상 적용.
- 수용 기준: 8.1 #14.
- 퀴즈 안의 글은 STORY 2장·CURRICULUM 규정대로 유지(이 장 대상 아님).

## 8. 수용 기준 (Done 조건)
### 8.1 기능
1. 비트 1~12 각각에 대응하는 컷신 12개 + 중간 비트 4-1~4-5 오버레이 5개(총 17개)가 `data/cutscenes.ts`에 존재하고 STORY 비트 번호(`beat`, 중간 비트는 `beat:4` + `mid:1~5`)로 조회된다.
2. 컷신 데이터에 **문자열 필드가 없다**(`bubble.text` 부재). 린트 규칙: `data/cutscenes.ts`에서 한글 문자열 리터럴 0건.
3. 모든 컷신은 길이 5~25초, 중간 비트 오버레이는 7~10초, 전부 건너뛰기 가능(C11은 최초 시청에 한해 1초 길게 누르기, 재시청은 즉시). 건너뛰어도 `onEnd` 결과(비트·mid·플래그·게이지 표시·저장)는 정상 종료와 동일.
4. 컷신 중 `paused()`가 true(lockInput 컷신), 종료 시 입력·카메라 복귀, 일시정지 후 재개 시 타임라인 정확히 이어짐.
5. 신규 세이브(`S.story = {beat, mid, seen, ended?, hints?}` — STORY 7.1과 필드 일치) 마이그레이션 후 기존 세이브가 깨지지 않는다(`save-schema` 단위 테스트: `mid` 기본 0, `seen` 17키 기본 0, `mid≠0`이면 `beat===4`).
6. 사과 게이지·경계 👁️·가방 개수 등 스토리 HUD에 **문장이 없다**(DOM 텍스트 노드 검사 E2E).
7. 튜토리얼 힌트 13종이 각 트리거에서 1회 표시, 성공 시 소멸, 재표시 규칙 동작(E2E).
8. 컷신 12개 총 154초(최초 시청 ~2.6분 ± 20%), 중간 비트 5개 45초, 합계 199초(~3.3분).
9. `iconToast`가 존재하고 스토리·튜토리얼 경로에서 `toast()` 호출이 0건(저장 실패 등 시스템 오류 제외, grep/린트 검사).
10. 사과 게이지 = `S.earned ÷ APPLE_PRICE`(소비해도 불변)이며, 일반 수입만으로는 60%에서 멈추고(4-5 발동) 삼성 판매(가격의 ~40%) 후 C08 종료 시 100%(단위 테스트). C05 미리보기는 실제 값을 바꾸지 않고, C08은 60%→100%로 재생.
13. 중간 비트 4-1~4-5: 각 7~10초, `lockInput:false`로 재생 중 이동 입력이 유지되고, 발동 조건·`mid` 갱신·`seen`이 STORY 4.1 표와 일치(E2E: 구역 진입 시뮬레이션).
14. 연출 보호 구간(비트 5~C12): 일반 의뢰·업적·N14·일일 보너스 알림이 C12 종료 전까지 0건이고 종료 직후 요약 1개 + ☰ 점으로 표시, 추격 ⚠·화살표·시스템 오류 toast는 정상 표시(E2E).
11. `aria-label`은 한 단어만 사용하고 시각 텍스트로 노출되지 않는다. 컷신 재시청 메뉴(🎞️)는 `S.story.ended` 이후에만 노출.
12. 첫 실행 시 OS 모션 감소 설정이 인게임 토글에 자동 반영된다.

### 10.3 HUD 슬롯 격자 · 상한 · 우선순위 · 숨김 규칙
**상한**: 동시 표시 HUD 위젯 **6개 이하**(조이스틱·A·점프 제외). 이 중 상시 3개(💰·🍎·☰), 상황 3개. 주의 슬롯(TC)은 **한 번에 1개**, 방향 화살표도 **한 번에 1개**.

#### 10.3.1 슬롯 정의 (모바일 가로 844×390 기준, 세이프 에어리어 내부)
```
 x:0                                                       x:844
 ┌───────────────────────────────────────────────────────────┐
 │ TL                  TC                              TR    │ y 8
 │ 💰 12,340           [ 주의 슬롯 1개 ]              ❗2 ☰  │  ← 높이 48
 │ 🍎 ▮▮▮▮▮▯▯▯  (60w)    (👁눈꺼풀 / ⚠ / 🚨)          (44px) │
 │ ⚡▓▓▓░  ← 상황(L1)                                        │ y~84
 │ 🎒 ●●○  ← 상황(L2)                      [⏭]  ← R-mid    │
 │                                                           │
 │   ⮕ 🏠  ← 방향 화살표: 화면 가장자리 호, 1개              │
 │                                                           │
 │  ╭───────╮   ← 위험구역 BL 금지: 말풍선·화살표·토스트    │
 │  │ 조이  │                                   (↑)  ( A )  │
 │  │ 스틱  │   (바깥 링 = 달리기)               60    76   │
 │  ╰───────╯                                               │
 └───────────────────────────────────────────────────────────┘
```
- **TL**: 💰 숫자(20px 굵게) / 아래 🍎 게이지(가로 60px, 8눈금). 이 둘이 항상 같은 열에서 수직으로 붙는다(돈과 목표를 한 시선에서).
- **TC**: 주의 슬롯 1개. 우선순위 큐 → **잡힘/추격(⚠ spike) > 경계 상승(눈꺼풀+🚨) > 수호신 시선(👁️) > 의뢰 변화(❗) > 이동수단 연료 경고**. 낮은 것은 큐 대기(최대 1.5초씩), 추격 중엔 추격만.
- **TR**: `☰`(44×44) + 그 왼쪽 `❗n` 의뢰 배지(진행 중 의뢰 수, 탭하면 의뢰 목록으로 직행). 경계 위젯은 TC에서만, TR에는 두지 않는다.
- **L1/L2(상황 칩)**: 스태미나는 **가득이면 숨김**(100%→1.5초 후 페이드), 달리는 중·회복 중에만 표시. 🎒는 **들고 있거나 가득일 때만**. 이동수단 연료는 탑승 중에만 L1을 대체(스태미나 숨김; 탑승 중 스태미나 달리기 비활성이므로 충돌 없음).
- **R-mid**: ⏭(컷신 중) 또는 의뢰 미니 트래커(아이콘 줄 최대 3개, 변화 시 3초만 펼침 후 `❗n` 배지로 접힘).
- **하단 중앙**: `#prompt`는 제거하고 **A 버튼 자체가 대상 픽토그램으로 변신**(10.4). 데스크톱은 하단 중앙에 `[E] 대상` 칩 유지.

#### 10.3.2 최악 시나리오(전부 동시): 수배 ★3 + 추격 + 가방 + 탑승 + 의뢰
표시: 💰 · 🍎 · ☰/❗ (상시 3) + TC `⚠ 추격` + L1 `연료` + L2 `🎒` = **6개 = 상한**. 이때 *숨김 순서*(상한 초과 시 아래 순으로 먼저 사라짐): ①의뢰 미니 트래커 → ②스태미나(탑승 시 이미 대체) → ③🎒 칩(가득 경고만 TC로 승격 시 제거) → ④💰 숫자(아이콘만) → 절대 숨기지 않음: 🍎·TC 주의·방향 화살표 1개.
- 방향 화살표 대상 우선순위: **추격 중 🏠(기지) > 위험 쐐기 > 활성 의뢰 ❗ > 🍎 수집 목표**. 추격 중 다른 화살표는 즉시 숨김.
- `#lines`/`addHudLine`: **문자열 줄 금지**로 전환. 시스템 `hud()`는 `HudWidget{slot, priority, icons[], fill?}`를 반환(타입은 코드 보고 대상). 슬롯당 위젯 수 상한을 렌더러가 강제.
- 정보 숫자는 **💰만 허용**. `#inc`(+x/s)는 평상시 숨김, 💰 길게 누르기/호버 시 말풍선 1회.
- `#info`(행성 이름·수치·fact 문장): 월드에선 비노출(4.3 유지), 도감/상점 상세에서만. 조준 십자(`#cross`) 대상 행성은 **실루엣 + 등급 점(●1~5)**만.

#### 10.3.3 데스크톱 (≥700px)
```
┌─────────────────────────────────────────────────────────────┐
│ 💰 12,340                [ 주의 슬롯 ]                 ❗2 ☰ │
│ 🍎 ▮▮▮▮▮▯▯▯                                                 │
│ ⚡▓▓▓░ (달릴 때만)                                          │
│ 🎒 ●●○ (들 때만)                                            │
│                         ✚                                   │
│                    [E] 🎒 대상 칩                           │
│                     ⮕🏠                                     │
└─────────────────────────────────────────────────────────────┘
```
키 보조 단축키(`B`도감 `I`가방…)는 ☰ 항목에 키캡을 병기(툴팁 없음, 키캡 모양 칩). 마우스 클릭 시점 고정 버튼(`🔒 시점`)은 **UI에서 제거**하고 화면 클릭 자체가 고정(Esc 해제)로 동작. 해제 상태 표시는 가장자리 마우스 아이콘(🖱️) 1개.

### 10.4 일관된 상호작용 규칙 — "버튼 하나로 무엇이든"
**규칙**: 한 시점에 *가장 가까운 대상 하나*가 있고, 그 대상의 *주 행동*은 **E(데스크톱) / A(모바일) 한 입력**이다. 행동 종류는 A의 **픽토그램이 바뀌어** 알린다.

| 대상 | A/E 의 행동 | A 버튼 표면 |
|---|---|---|
| 둥지 행성 | 줍기(퀴즈 개시) | 🪐 |
| 가방 든 상태 + 기지 슬롯 | 입고 | 🎒⬇ |
| 암시장 상인/판매대 | 판매 (현재 `F` → E로 통합) | 💰 |
| 문 | 시험 시작 | 🚪 |
| 의뢰 NPC | 수락/완료 | ❗ / ✅ |
| 탈것(탑승 가능) / 탑승 중 | 탑승 / 하차 (현재 `V`) | 🛹 / 🚀 → 탑승 중 `⏏` |
| 포탈 패드 | 목록 열기 | 🌀 |
| 대상 없음 | **자세 변경 없음**(A 숨김) | — |
- **같은 대상에 행동이 둘 이상**(예: 상인에게 판매·구매)일 때만 *보조 입력*을 허용: 데스크톱 `F`, 모바일은 A **길게 누르기 0.4초**(링이 채워짐) — 보조 행동은 되돌릴 수 있거나 비파괴(상점 열기)만. 파괴적 행동(버리기)은 보조에도 두지 않고 ☰ 안에서만.
- **우선순위(대상 동률 시)**: 문 > 의뢰 완료 ✅ > 입고 > 판매 > 줍기 > 탑승. 근접 거리 동일하면 시선 중앙에 가까운 것.
- 무효 상태(가방 가득·돈 부족 등)에도 A는 **눌린다**: 대신 *거절 피드백*(10.9 실패)을 재생 — 버튼을 회색으로 만들어 무반응처럼 느끼게 하지 않는다(현 `#prompt.off` opacity 0.5를 폐기).
- 키 재배치(구현 시 `input.ts`·`systems/ui.ts` 영향): `E`=주, `F`=보조, `Space`=점프/(탑승 시 상승), `Shift`=달리기/부스트, `C`=하강, `Tab`/`Esc`=☰·뒤로, `B`=도감 직행. `V`·`G` 전용 키는 **A 통합 후 고급 단축키로만 유지**(GAMEPLAY 1.2의 "확정 결정 3"은 *키 배정* 결정이므로 유지하되, 모바일 전용 버튼 🛹/🚀/🌀 추가는 **취소**하고 A로 흡수).

#### 10.4.1 모바일 엄지 영역
- 화면 가로 844×390 기준 오른쪽 엄지의 편한 반경 ≈ 140px (오른쪽·아래 모서리에서). 이 안에 **A(76px) + 점프(60px) 두 개만** 둔다.
  - `A`: right 28 / bottom 36 (가장 쉬운 곳). `점프(↑)`: right 118 / bottom 100 (A 위쪽 호). 두 버튼 중심 거리 ≥ 96px(오조작 방지, 터치 영역 최소 44px 확보).
  - **달리기 버튼 폐지** → 조이스틱을 *끝까지* 밀면 바깥 링에서 달리기(스태미나 소모). 안쪽 원 = 걷기. 시각: 바깥 링 점선, 달리기 중 링이 채워짐. 설정에 "달리기 토글 버튼 켜기"(🏃) 옵션 제공(접근성: 조이스틱 끝 밀기 어려운 사용자).
  - 비행: 점프 위치 버튼이 `⬆`로 바뀌고, 우주선에서만 그 아래/위에 `⬇` 추가(최대 3버튼). 부스트는 달리기와 동일하게 조이스틱 바깥 링.
- 조이스틱: 좌하 고정 대신 **왼쪽 절반 어디든 첫 터치에 생성**(플로팅). 기존 `#joy`(130px)는 시각 가이드로 유지, 고정 위치 선호 설정 제공. 그 위 140px는 HUD 금지(4.2 유지).
- 카메라 회전은 **오른쪽 절반의 빈 영역 드래그**. A/점프 버튼 위에서 시작한 터치는 카메라로 가지 않도록 `touchstart` 대상 검사(현재 body `touch-action:none`).
- 모든 버튼 **최소 44×44, 권장 48×48**, 인접 버튼 간격 ≥ 12px. ☰는 44px 정사각, 상단 우측 여백 `max(8px, env(safe-area-inset-right))`.
- 노치/둥근 모서리: 좌우 세이프 에어리어 + 조이스틱·A는 바닥에서 `max(24px, env(safe-area-inset-bottom))`.

### 10.5 메뉴 구조 (탭 수·깊이·뒤로가기)
**규칙**: ① 최상위 허브 1개(`☰`), ② 한 화면 탭 ≤ 5, ③ 깊이 ≤ 2(허브 → 화면 → 상세/서브칩), ④ **좌상단 `◀` 항상 동일 위치**(한 단계 뒤로). 최상위 화면의 `◀`은 월드로 복귀. `✕` 단독 버튼은 폐지(`◀`가 닫기 겸용), 배경 탭=닫기(퀴즈 제외), `Esc`/모바일 뒤로가기 = `◀`, `B`/`Tab` = 허브 토글.

### 10.6 퀴즈 모달 가독성 · 피드백
현재: 카드 460px, 질문 15px(데스크톱)/14px(모바일), 보기 버튼 padding 10px, `qr` 해설 12px 회색, 정오는 테두리 색만.
**개선**
1. **레이아웃**: 모바일 가로(높이 ≈ 360px)에서는 *좌: 문제·그림, 우: 보기 2×2 격자* 로 분할(스크롤 없이 한 화면). 세로/좁은 화면은 문제 위·보기 아래 단일 열. 카드 `max-height: 94dvh`, 내부만 스크롤.
2. **글자**: 문제 16~18px(모바일 16px 하한), 줄간격 1.6, 본문색 `--fg` 풀명도. 해설은 14px `--fg` 80%(현 12px `--dim`은 폐기). 보기 최소 높이 **52px**, 보기 간 간격 10px, 한 줄 40자 초과 시 자동 줄바꿈(`text-align:left` 유지).
3. **보기 식별자**: `1. 2. 3. 4.` 숫자(키보드 1~4는 유지) 대신 앞에 **도형 칩 ● ■ ▲ ◆**(색 아님, 모양). 키보드 안내는 도형 옆에 작은 키캡 `1`~`4`. 해설에서 보기를 가리킬 때도 같은 도형.
4. **정오 피드백(색+모양+소리+진동 4중)**: 선택 즉시 ①정답 보기 좌측에 **✅ 체크 배지 + 두꺼운(3px) 실선 테두리**, ②오답 선택은 **❌ 배지 + 점선 테두리 + 좌우 흔들림 0.25s(모션 감소 시 정지)**, ③카드 상단 중앙에 큰 아이콘 1개(✅/❌ 48px) 팝, ④소리(상승 2음/하강 2음), 진동(정답 30ms, 오답 40ms×2). 기존 `정답!/오답` 글자와 색만 의존 코드는 폐기. 다만 *해설은 글로 유지*(교육 내용).
5. **진행**: `(1/3)` 글자 → 카드 상단 **점 ●●○**(현재 칸 확대, 맞은 문제 ✅ 점). `need` 충족 가능성은 표시하지 않음(압박 방지).
6. **다음 버튼**: 정오 표시 후 해설 아래가 아니라 **카드 하단 고정 바**(전폭 56px, `▶`+키캡 Space). 정답이면 자동 진행 옵션(설정, 기본 꺼짐, 2.5초).
7. **`✕`**: 닫을 때 *한 문제라도 답했으면 결과 반영*(기존 코드 동작)은 오조작 위험 → ✕ 탭 시 작은 확인 시트(🚪 vs ↩, 아이콘 2개)로 한 번 더 확인. 아무것도 답하지 않았다면 즉시 닫힘(손해 없음).
8. **시간 정지 표시**: 퀴즈 열리면 월드 흑백 + 상단에 ⏸ 아이콘(5.2의 ⏳ 대체). 결과가 *경계/잡힘*과 연결되는 퀴즈(문 시험·보스)는 카드 테두리에 `spike` 점선으로 "실패 시 위험"을 형태로 예고.
9. 이미지 문제(관측형)는 그림이 보기보다 먼저 보이도록 문제 영역을 **최소 40% 높이**로 확보하고 핀치 확대 허용.

### 10.8 접근성·색약·모션 감소 보강 (A1~A14 위에 추가)
- **색 토큰**: 6.2의 `--ok/--warn/--danger/--gold`를 `:root`에 추가하고 코드의 하드코딩(`quiz.ts`의 `#7cf09a/#ff7a8a`, `hud.css` `#stam`·`#stam.tired`)을 토큰으로 이전. 정오·스태미나는 이미 모양 병행 규정(💤, ✅/❌).
- **색약 보조 모드(설정 토글)**: 위험=보라/주황 대비 강화 팔레트 + 모든 `spike` 외곽을 굵은 점선 + 게이지 채움에 사선 패턴. 기본 팔레트도 `--ok`↔`--danger` 명도차 ≥ 40%(6.2) 유지.
- **모션 감소**: `@media (prefers-reduced-motion: reduce)` + `body.rm`(설정 토글)로 공통 처리: 흔들림 0, 팝은 페이드 0.15s, 위험 쐐기는 정적, 맥동 → 정적 외곽. **현재 CSS에 해당 미디어 쿼리가 없으므로 신규 추가**.
- **진동**: `navigator.vibrate`는 모바일 옵션(기본 켬): 정답 30ms / 오답 40-60-40 / 잡힘 200ms / 위험 쐐기 진입 20ms 1회(연속 진동 금지). 현재 코드에 0건이므로 래퍼(`haptics.ts`) 신설 필요.
- **확대·글자 크기**: 설정에 UI 크기 3단(100/115/130%). 모든 HUD 크기는 `rem` 기반으로 하여 `--ui` 배율로 조절(현재 12/11px 고정값은 모바일 최소 11px → 이후 `calc(11px*var(--ui))`).
- **외부 입력**: 포커스 순서는 허브 타일 → 화면 탭 → 목록; `Enter`=선택, `◀`/Esc=뒤로. 방향키로 타일·격자 이동(roving tabindex).
- **한 손 모드(옵션)**: 설정에서 UI 좌우 반전(조이스틱 우측/액션 좌측) 제공.

### 10.10 구현 우선순위 (UI 한정, 독립 병합 가능)
1. **P0 (코드 영향 작음, 효과 큼)**: 탭·버튼 터치 영역 44px 확보, 퀴즈 정오 ✅/❌ + 보기 도형 + 폰트 확대, `✦`→`💰`, `🈵` 제거, `#keys`·`.how` 문장 → 픽토그램, `prefers-reduced-motion` CSS.
2. **P1**: HUD 슬롯 격자 + `HudWidget` 추상화(`addHudLine` 대체), 숨김 규칙(스태미나·가방·경계), 점진 공개 플래그(`S.ui.seen`).
3. **P2**: A 단일 버튼 + 조이스틱 바깥 링 달리기(입력 시스템 변경), `☰` 허브 + `◀` 규칙, 상점 4탭 재편, 도감 구역 칩·하단 시트.
4. **P3**: 위험 방향 쐐기, 햅틱 래퍼, 색약 보조 모드, UI 크기 배율, 핵심 SVG 아이콘 13개.

### 10.11 수용 기준 (10장 추가분)
1. 모바일 390×844·844×390·667×375에서 **상시+상황 HUD 위젯 ≤ 6**, 모든 터치 타깃 ≥ 44×44, 인접 터치 타깃 간격 ≥ 12px(E2E에서 `getBoundingClientRect` 검사).
2. 최악 시나리오(10.3.2) 스냅샷에서 조이스틱 영역(좌하 140px)에 HUD/쐐기/화살표 0개.
3. 방향 화살표 동시 표시 ≤ 1, 주의 슬롯(TC) 동시 표시 ≤ 1(단위 테스트: 큐 우선순위).
4. 신규 세이브의 첫 4분 동안 💰·🍎·☰·스태미나가 10.2 표의 시점에 처음 나타난다(`S.ui.seen`).
5. 모든 메뉴 화면에서 `◀` 위치가 동일(좌상단 ±2px)하고, 허브 기준 깊이 ≤ 2, 한 화면 탭 ≤ 5.
6. 퀴즈: 정/오 상태를 *색 제거(그레이스케일) 스크린샷*에서 도형·테두리 스타일만으로 판별 가능, 모바일 가로에서 스크롤 없이 문제+보기 4개 표시.
7. A/E 단일 입력으로 줍기·입고·판매·문·의뢰·탑승·포탈이 모두 동작(상호작용 표 전수 E2E). 무효 상태에서 A 누르면 거절 피드백 재생.
8. `prefers-reduced-motion` 및 `body.rm`에서 흔들림·맥동·쐐기 애니메이션 0, 번쩍 ≤ 3Hz(A4 유지).
9. 무작위 테스터 5명 이상이 글·음성 안내 없이 4분 안에 줍기→퀴즈→복귀→판매 성공 4/5 이상.
