# 그래픽 향상 계획 (PC / 모바일 2단계 품질)

## Context
지금 게임은 로우폴리 정점 색 + 램버트 조명 하나(반구광 + 직사광)뿐이다. 그림자·구름·후처리·반사가 없고, 밤 불빛은 광원이 아니라 "밝게 칠한 면"이다. 하늘은 단색 돔 + 별 + 해·달 스프라이트다. 품질 설정이 아예 없고, 모바일 대응은 군중 수 제한(36)과 픽셀비 2 제한뿐이다.
목표: 로우폴리의 미술 방향(박스형 캐릭터, 그림 중심)은 **그대로 두고**, 빛·하늘·물·밤·날씨로 "한 단계 고급스러운" 화면을 만든다. 품질은 **PC 프로필 / 모바일 프로필** 두 벌로 나누고, 같은 코드에서 기능 스위치만 다르게 켠다. 자동 감지 + 설정에서 수동 변경도 가능하게 한다.

## 현황 (조사 결과)
- 렌더러: `render/world.ts:27` `new THREE.WebGLRenderer({antialias:true})`, 픽셀비 ≤2. 톤매핑·출력 인코딩·그림자 설정 없음.
- 조명: `render/sky.ts:118-172` 반구광 1 + 직사광 1, 색은 `lowpoly/palette.ts`의 `TINT`. 안개 160~520. 그림자·`castShadow` 전무.
- 하늘: `paintDome`(링 색을 매 프레임 칠하는 정점색 돔), 별 `Points`, 해·달 스프라이트. **구름 없음**.
- 날씨: `render/weather.ts` 단일 `Points`(최대 260), 눈·불씨·안개·파편·포자. 비는 없음.
- 물: `render/water-shader.ts` 커스텀 셰이더(파도 5, 프레넬, 반짝임, 거품). 실제 반사 없음.
- 재질: Lambert 24 / Basic 29 / Standard 2 / Shader 1. 병합 지오메트리(`lowpoly/merge.ts`의 `lowMat`, `glowMat`, `instancedChunks`)가 기본이라 호출 수가 낮다.
- 후처리·렌더 타깃·환경맵 없음. three는 CDN r128 UMD 한 개뿐이고 examples(EffectComposer 등)는 안 불러온다. 테스트 픽스처(`tests/e2e/fixtures.ts`)가 three를 로컬로 대체하므로 추가 스크립트는 `tests/vendor`에 같이 넣어야 한다.
- 이미 있는 재사용 자산: `setSurfaceDetailEnabled`(품질 토글 선례, `render/surface-detail.ts:147`), `nightMeshes`(밤 전용 메시), `updateSky` 매 프레임 훅, `instancedChunks` 거리 청크, 디버그 오버레이(`debug.ts`, `renderer.info`).
- 예산: 스폰 시야 삼각형 ≈94k~110k, 호출 ≈392(스폰 시야, `docs/tech/TEXTURES.md`). 실GPU 60fps는 보장 안 됨. SwiftShader 기준 fps ≈43.
- 한계: E2E는 실GPU 성능·터치·화질을 판정할 수 없다. 화질 확인은 렌더 정보(삼각형·호출) 수치, 픽셀 읽기, 스크린샷 육안으로 한다.

## 1. 품질 시스템 (모든 것의 바탕, 먼저 한다)
- `core/quality.ts` (신규): 프로필 `desktop | mobile` + 기능 스위치 객체 `Q`(그림자, 구름 종류, 반사, 블룸, 비 입자 수, 나무 흔들림, LOD 배율, 픽셀비 상한…).
  - 자동 감지: 기존 `TOUCH`(`systems/input.ts`) + `navigator.deviceMemory`/`hardwareConcurrency` + 화면 크기. 시작 시 프로필을 정한다.
  - **적응형**: 프레임 시간이 3초 동안 30fps 미만이면 한 단계 낮추고(해상도 배율 → 그림자 → 후처리 순), 안정되면 올리지 않는다(깜빡임 방지).
  - 수동: 설정 화면에 "그래픽: 자동 / PC / 모바일 / 절전". 세이브에 `S.gfx` 필드 추가(`core/save-schema.ts`, 기본값 병합이라 버전 올림 불필요).
  - 개발용: URL `?gfx=desktop|mobile`로 강제(E2E가 두 프로필을 모두 검증).
- 렌더러 공통 개선(두 프로필 모두): `outputEncoding = sRGB`, `toneMapping = ACESFilmic`(노출 낮/밤 보간), `powerPreference:'high-performance'`.
  - **위험**: 톤매핑·인코딩을 켜면 지금의 모든 색이 달라진다. `palette.ts`·`TINT`를 한 번 재조정하고 스크린샷으로 비교한다. 문제가 크면 인코딩은 유지하고 톤매핑만 단계 적용.
- 프로필별 목표 예산: 모바일 삼각형 ≤60k / 호출 ≤250 / 픽셀비 ≤1.5. PC 삼각형 ≤110k / 호출 ≤450 / 픽셀비 ≤2. `?gfx=`별 E2E 예산 검증.

## 2. 하늘·구름 (가장 눈에 띄는 효과, 사용자 요청)
- **구름**
  - 모바일: 로우폴리 구름 덩어리 15~25개. 작은 20면체 여러 개를 합친 구름 지오메트리를 인스턴싱하고, 바람 방향으로 천천히 흐른다. 시간대에 따라 색이 변한다(낮 흰색, 일몰 분홍·주황, 밤 어두운 남색, 비 오는 날 회색). 호출 1~2개.
  - PC: 위에 더해 하늘 돔에 노이즈(fbm) 구름층 셰이더를 한 겹 얹는다. 해 쪽 가장자리에 밝은 테두리, 이동·변형 애니메이션. 낮은 구름띠는 산 뒤 지평선에 층층이 깔린다.
  - 구름 그림자: 구름 아래 땅에 느리게 지나가는 어두운 얼룩(PC만, 지형 셰이더에 노이즈 마스크 곱).
  - 날씨 연결: 맑음/흐림/비 상태가 구름 개수·밀도·색을 바꾼다.
- **하늘색**: 지평선~천정 3단 그라데이션, 일출·일몰 때 해 방향 주변이 번지는 색, 안개 색과 하늘 색 일치(경계 안 보이게).
- **빛 연출**: 해 주변 후광, 구름 틈 빛줄기(가짜 광선: 해 방향 가산혼합 띠 몇 장, PC), 별 반짝임, 가끔 떨어지는 별똥별, 달 위상.
- **분위기 요소**: 철새 무리(인스턴싱 V자 비행), 비 온 뒤 무지개(PC), 산악 위 오로라(밤·PC, 셰이더 띠), 먼 산 뒤 안개층(공기 원근), 지평선 연기 한 줄기(시골 섬).
- 파일: `render/sky.ts`(돔·광원), 신규 `render/clouds.ts`, `render/sky-fx.ts`(별똥별·오로라·무지개·새), `systems/daynight.ts`(연동).

## 3. 빛과 그림자
- **정점 AO 굽기 (두 프로필 공통, 런타임 비용 0)**: 병합 지오메트리를 만들 때 건물 아래·모서리·도로 가장자리·나무 밑 정점색을 어둡게. `lowpoly/merge.ts`에 `bakeAO` 단계를 추가하고, 도심 재설계(JSON 건물 굽기)와 같은 시점에 적용.
- **PC: 그림자 맵**: 직사광 그림자가 플레이어를 따라다닌다(근거리 약 70u, 2048). 그림자를 던지는 것은 캐릭터·차·근처 건물·나무. 먼 건물은 제외(`castShadow`를 청크 거리로 토글). 해가 낮아질수록 길어지고, 밤은 달빛으로 약하게.
- **모바일: 접촉 그림자**: 캐릭터·차·동물·나무 밑에 둥근 어두운 판(인스턴싱 한 번). 해 방향으로 살짝 늘려 방향감을 준다. 그림자 맵은 끈다.
- **하늘 조명 개선**: 반구광 색을 하늘 3단 그라데이션과 맞추고, 그림자 색을 푸른빛으로 틴트해 입체감을 키운다.

## 4. 물·반사·유리
- 호수·바다: **PC** 근거리 평면 반사(절반 해상도 렌더 타깃, 호수 근처에서만), 모바일은 기존 셰이더에 하늘·구름 색 프레넬 + 반짝임 강화(반사 렌더 없음). 파도 법선 흐름, 해안 거품, 얕은 곳 투명도는 두 프로필 공통 개선.
- **차 도장·창문(PC)**: 하늘을 한 번 큐브맵으로 구워(시간대 몇 단계마다 갱신) 차체·유리창 재질에 환경 반사. 모바일은 차체에 하늘 색 그라데이션 정점색만.
- **젖은 도로(비 올 때, PC)**: 도로 색을 어둡게 하고 가로등·헤드라이트가 길게 비친다(세로 가산 띠 데칼).

## 5. 밤과 불빛
- **PC**: 블룸(밝은 부분 번짐, 절반 해상도). EffectComposer 스크립트(CDN)를 로컬 vendor에도 두고 픽스처 라우트를 확장. 가로등·창문·네온·헤드라이트가 번진다. 헤드라이트는 실제 스포트라이트 최대 2~4개(차량 근처만).
- **모바일**: 후처리 없이 **가짜 글로우**: 가로등·창문·헤드라이트 위치에 가산혼합 후광 판을 인스턴싱(청크·거리 컬링). 헤드라이트 빛 원뿔 메시. `nightMeshes` 패턴을 재사용.
- 창문 불빛이 일정 확률로 꺼졌다 켜지게, 가로등은 해질 때 순차 점등(저비용 애니메이션, 두 프로필 공통).

## 6. 날씨·식물
- **비**: 비 줄기 인스턴싱(PC 600 / 모바일 200), 땅 튀김 링, 우산 없을 때 화면 가장자리 물방울(CSS), 천둥번개(구름 발광 + 화면 번쩍임 + 지연된 소리).
- **눈 쌓임 느낌**: 설산 지형색을 눈 날씨에 서서히 밝게(셰이더 마스크).
- **안개 띠**: 호수·계곡 위 낮은 안개 스프라이트(새벽에 짙게).
- **나무·풀 흔들림**: 바람 정점 셰이더(`surface-detail.ts`의 `onBeforeCompile` 방식 재사용). PC는 풀 다발 인스턴싱, 모바일은 나무만 약하게 흔들림.
- 꽃가루·낙엽·반딧불(밤 숲) 같은 소량 입자(PC), 모바일은 반딧불만.

## 7. 후처리·색보정·표현
- 공통: 톤매핑 ACES, 시간대별 색 온도(아침 청량, 낮 선명, 일몰 따뜻, 밤 푸른 톤).
- PC: 약한 비네팅·색수차 없음·부드러운 색 그레이딩, 선택 옵션 "고급"에서 SSAO(r128 예제 패스, 기본 끔).
- 모바일: CSS 비네팅 오버레이 한 장만(GPU 비용 거의 없음).
- 캐릭터(PC): 반전 껍질 외곽선(두께 0.02)으로 만화 같은 윤곽. 모바일은 끈다. 박스형 로블록스 미감을 유지.
- 계획에 넣지 않는 것: 실제 레이트레이싱·전역조명·고해상도 PBR 텍스처(로우폴리 분위기와 맞지 않고 모바일에서 불가능).

## 9. 위험과 대응
- **톤매핑·인코딩 변경이 모든 색을 바꿈**: G0에서 먼저 하고 전후 스크린샷을 비교한다. 문제가 크면 단계 적용·`Q`로 끌 수 있게.
- **추가 스크립트(EffectComposer)**: CDN r128 호환 버전을 고정하고, `tests/vendor`에 복사해 픽스처 라우트 확장. 로딩 실패 시 후처리 없이 계속 동작(폴백).
- **모바일 성능을 이 환경에서 못 잼**: 렌더 정보 수치와 적응형 강등을 안전장치로 두고, 실제 기기 점검 목록(아이폰 사파리, 중급 안드로이드)을 문서에 적는다. 이것은 사용자 확인이 필요하다.
- **그림자 맵 비용·떨림**: 범위를 플레이어 중심 스냅(텍셀 단위)으로 고정해 떨림을 막고, 캐스터를 거리 청크로 제한.
- **삼각형 예산**: 구름·새·글로우 판은 인스턴싱이라 삼각형이 작다. 도심 재설계의 110k 한도와 합쳐서 `zz-tris`로 항목별 측정한다.
- **500줄 제한**, 문서(`docs/tech/`)·`COORDINATION.md` 갱신, 마일스톤마다 커밋.

## 10. 검증
- `cd client && npx tsc` 무오류.
- `?gfx=desktop`, `?gfx=mobile` 두 프로필로 스폰 시야 `renderer.info`(삼각형·호출)가 프로필별 예산 이내.
- 픽셀 검사 E2E: 하늘 영역에 구름 픽셀이 있다(밝기 분산), PC에서 캐릭터 아래 그림자 픽셀이 더 어둡다, 밤 글로우 픽셀이 밝다, 비 날씨에 줄기 픽셀 존재.
- 프로필 스위치: 설정 변경이 즉시 반영되고 세이브·복원 된다. 적응형 강등이 인위적 지연(느린 프레임 주입)에서 동작한다.
- 기존 전체 E2E 통과(톤매핑 변경으로 색에 의존하는 픽셀 테스트는 조정).
- 스크린샷(`tests/out/gfx-*.png`): 낮·일몰·밤·비 × PC·모바일 8장을 나란히 육안 비교. 마지막에 실제 기기(모바일·PC)에서 사용자가 확인.
