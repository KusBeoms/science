# 그래픽 향상 계획 (PC / 모바일 2단계 품질)

## Context
지금 게임은 로우폴리 정점 색 + 램버트 조명 하나(반구광 + 직사광)뿐이다. 그림자·구름·후처리·반사가 없고, 밤 불빛은 광원이 아니라 "밝게 칠한 면"이다. 하늘은 단색 돔 + 별 + 해·달 스프라이트다. 품질 설정이 아예 없고, 모바일 대응은 군중 수 제한(36)과 픽셀비 2 제한뿐이다.
목표: 로우폴리의 미술 방향(박스형 캐릭터, 그림 중심)은 **그대로 두고**, 빛·하늘·물·밤·날씨로 "한 단계 고급스러운" 화면을 만든다. 품질은 **PC 프로필 / 모바일 프로필** 두 벌로 나누고, 같은 코드에서 기능 스위치만 다르게 켠다. 자동 감지 + 설정에서 수동 변경도 가능하게 한다.

## 현황 (조사 결과)
- 렌더러: `render/world.ts:27` `new THREE.WebGLRenderer({antialias:true})`, 픽셀비 ≤2. 톤매핑·출력 인코딩·그림자 설정 없음.
- 조명: `render/sky.ts:118-172` 반구광 1 + 직사광 1, 색은 `lowpoly/palette.ts`의 `TINT`. 안개 160~520. 그림자·`castShadow` 전무.
- 하늘: `paintDome`(링 색을 매 프레임 칠하는 정점색 돔), 별 `Points`, 해·달 스프라이트. **구름 없음**.
- 날씨: `render/weather.ts` 단일 `Points`(최대 260), 눈·불씨·안개·파편·포자. 비는 없음.
- 물: `render/water-shader.ts` 커스텀 셰이더(파도 5, 프레넬, 반짝임, 거품). 실제 반사 없음.
- 재질: Lambert 24 / Basic 29 / Standard 2 / Shader 1. 병합 지오메트리(`lowpoly/merge.ts`의 `lowMat`, `glowMat`, `instancedChunks`)가 기본이라 호출 수가 낮다.
- 후처리·렌더 타깃·환경맵 없음. three는 CDN r128 UMD 한 개뿐이고 examples(EffectComposer 등)는 안 불러온다. 테스트 픽스처(`tests/e2e/fixtures.ts`)가 three를 로컬로 대체하므로 추가 스크립트는 `tests/vendor`에 같이 넣어야 한다.
- 이미 있는 재사용 자산: `setSurfaceDetailEnabled`(품질 토글 선례, `render/surface-detail.ts:147`), `nightMeshes`(밤 전용 메시), `updateSky` 매 프레임 훅, `instancedChunks` 거리 청크, 디버그 오버레이(`debug.ts`, `renderer.info`).
- 예산: 스폰 시야 삼각형 ≈94k~110k, 호출 ≈392(스폰 시야, `docs/tech/TEXTURES.md`). 실GPU 60fps는 보장 안 됨. SwiftShader 기준 fps ≈43.
- 한계: E2E는 실GPU 성능·터치·화질을 판정할 수 없다. 화질 확인은 렌더 정보(삼각형·호출) 수치, 픽셀 읽기, 스크린샷 육안으로 한다.

## 1. 품질 시스템 (모든 것의 바탕, 먼저 한다)
- `core/quality.ts` (신규): 프로필 `desktop | mobile` + 기능 스위치 객체 `Q`(그림자, 구름 종류, 반사, 블룸, 비 입자 수, 나무 흔들림, LOD 배율, 픽셀비 상한…).
  - 자동 감지: 기존 `TOUCH`(`systems/input.ts`) + `navigator.deviceMemory`/`hardwareConcurrency` + 화면 크기. 시작 시 프로필을 정한다.
  - **적응형**: 프레임 시간이 3초 동안 30fps 미만이면 한 단계 낮추고(해상도 배율 → 그림자 → 후처리 순), 안정되면 올리지 않는다(깜빡임 방지).
  - 수동: 설정 화면에 "그래픽: 자동 / PC / 모바일 / 절전". 세이브에 `S.gfx` 필드 추가(`core/save-schema.ts`, 기본값 병합이라 버전 올림 불필요).
  - 개발용: URL `?gfx=desktop|mobile`로 강제(E2E가 두 프로필을 모두 검증).
- 렌더러 공통 개선(두 프로필 모두): `outputEncoding = sRGB`, `toneMapping = ACESFilmic`(노출 낮/밤 보간), `powerPreference:'high-performance'`.
  - **위험**: 톤매핑·인코딩을 켜면 지금의 모든 색이 달라진다. `palette.ts`·`TINT`를 한 번 재조정하고 스크린샷으로 비교한다. 문제가 크면 인코딩은 유지하고 톤매핑만 단계 적용.
- 프로필별 목표 예산: 모바일 삼각형 ≤60k / 호출 ≤250 / 픽셀비 ≤1.5. PC 삼각형 ≤110k / 호출 ≤450 / 픽셀비 ≤2. `?gfx=`별 E2E 예산 검증.

## 2. 하늘·구름 (가장 눈에 띄는 효과, 사용자 요청)
- **구름**
  - 모바일: 로우폴리 구름 덩어리 15~25개. 작은 20면체 여러 개를 합친 구름 지오메트리를 인스턴싱하고, 바람 방향으로 천천히 흐른다. 시간대에 따라 색이 변한다(낮 흰색, 일몰 분홍·주황, 밤 어두운 남색, 비 오는 날 회색). 호출 1~2개.
  - PC: 위에 더해 하늘 돔에 노이즈(fbm) 구름층 셰이더를 한 겹 얹는다. 해 쪽 가장자리에 밝은 테두리, 이동·변형 애니메이션. 낮은 구름띠는 산 뒤 지평선에 층층이 깔린다.
  - 구름 그림자: 구름 아래 땅에 느리게 지나가는 어두운 얼룩(PC만, 지형 셰이더에 노이즈 마스크 곱).
  - 날씨 연결: 맑음/흐림/비 상태가 구름 개수·밀도·색을 바꾼다.
- **하늘색**: 지평선~천정 3단 그라데이션, 일출·일몰 때 해 방향 주변이 번지는 색, 안개 색과 하늘 색 일치(경계 안 보이게).
- **빛 연출**: 해 주변 후광, 구름 틈 빛줄기(가짜 광선: 해 방향 가산혼합 띠 몇 장, PC), 별 반짝임, 가끔 떨어지는 별똥별, 달 위상.
- **분위기 요소**: 철새 무리(인스턴싱 V자 비행), 비 온 뒤 무지개(PC), 산악 위 오로라(밤·PC, 셰이더 띠), 먼 산 뒤 안개층(공기 원근), 지평선 연기 한 줄기(시골 섬).
- 파일: `render/sky.ts`(돔·광원), 신규 `render/clouds.ts`, `render/sky-fx.ts`(별똥별·오로라·무지개·새), `systems/daynight.ts`(연동).

## 3. 빛과 그림자
- **정점 AO 굽기 (두 프로필 공통, 런타임 비용 0)**: 병합 지오메트리를 만들 때 건물 아래·모서리·도로 가장자리·나무 밑 정점색을 어둡게. `lowpoly/merge.ts`에 `bakeAO` 단계를 추가하고, 도심 재설계(JSON 건물 굽기)와 같은 시점에 적용.
- **PC: 그림자 맵**: 직사광 그림자가 플레이어를 따라다닌다(근거리 약 70u, 2048). 그림자를 던지는 것은 캐릭터·차·근처 건물·나무. 먼 건물은 제외(`castShadow`를 청크 거리로 토글). 해가 낮아질수록 길어지고, 밤은 달빛으로 약하게.
- **모바일: 접촉 그림자**: 캐릭터·차·동물·나무 밑에 둥근 어두운 판(인스턴싱 한 번). 해 방향으로 살짝 늘려 방향감을 준다. 그림자 맵은 끈다.
- **하늘 조명 개선**: 반구광 색을 하늘 3단 그라데이션과 맞추고, 그림자 색을 푸른빛으로 틴트해 입체감을 키운다.

## 4. 물·반사·유리
- 호수·바다: **PC** 근거리 평면 반사(절반 해상도 렌더 타깃, 호수 근처에서만), 모바일은 기존 셰이더에 하늘·구름 색 프레넬 + 반짝임 강화(반사 렌더 없음). 파도 법선 흐름, 해안 거품, 얕은 곳 투명도는 두 프로필 공통 개선.
- **차 도장·창문(PC)**: 하늘을 한 번 큐브맵으로 구워(시간대 몇 단계마다 갱신) 차체·유리창 재질에 환경 반사. 모바일은 차체에 하늘 색 그라데이션 정점색만.
- **젖은 도로(비 올 때, PC)**: 도로 색을 어둡게 하고 가로등·헤드라이트가 길게 비친다(세로 가산 띠 데칼).

## 5. 밤과 불빛
- **PC**: 블룸(밝은 부분 번짐, 절반 해상도). EffectComposer 스크립트(CDN)를 로컬 vendor에도 두고 픽스처 라우트를 확장. 가로등·창문·네온·헤드라이트가 번진다. 헤드라이트는 실제 스포트라이트 최대 2~4개(차량 근처만).
- **모바일**: 후처리 없이 **가짜 글로우**: 가로등·창문·헤드라이트 위치에 가산혼합 후광 판을 인스턴싱(청크·거리 컬링). 헤드라이트 빛 원뿔 메시. `nightMeshes` 패턴을 재사용.
- 창문 불빛이 일정 확률로 꺼졌다 켜지게, 가로등은 해질 때 순차 점등(저비용 애니메이션, 두 프로필 공통).

## 6. 날씨·식물
- **비**: 비 줄기 인스턴싱(PC 600 / 모바일 200), 땅 튀김 링, 우산 없을 때 화면 가장자리 물방울(CSS), 천둥번개(구름 발광 + 화면 번쩍임 + 지연된 소리).
- **눈 쌓임 느낌**: 설산 지형색을 눈 날씨에 서서히 밝게(셰이더 마스크).
- **안개 띠**: 호수·계곡 위 낮은 안개 스프라이트(새벽에 짙게).
- **나무·풀 흔들림**: 바람 정점 셰이더(`surface-detail.ts`의 `onBeforeCompile` 방식 재사용). PC는 풀 다발 인스턴싱, 모바일은 나무만 약하게 흔들림.
- 꽃가루·낙엽·반딧불(밤 숲) 같은 소량 입자(PC), 모바일은 반딧불만.

## 7. 후처리·색보정·표현
- 공통: 톤매핑 ACES, 시간대별 색 온도(아침 청량, 낮 선명, 일몰 따뜻, 밤 푸른 톤).
- PC: 약한 비네팅·색수차 없음·부드러운 색 그레이딩, 선택 옵션 "고급"에서 SSAO(r128 예제 패스, 기본 끔).
- 모바일: CSS 비네팅 오버레이 한 장만(GPU 비용 거의 없음).
- 캐릭터(PC): 반전 껍질 외곽선(두께 0.02)으로 만화 같은 윤곽. 모바일은 끈다. 박스형 로블록스 미감을 유지.
- 계획에 넣지 않는 것: 실제 레이트레이싱·전역조명·고해상도 PBR 텍스처(로우폴리 분위기와 맞지 않고 모바일에서 불가능).

## 9. 위험과 대응
- **톤매핑·인코딩 변경이 모든 색을 바꿈**: G0에서 먼저 하고 전후 스크린샷을 비교한다. 문제가 크면 단계 적용·`Q`로 끌 수 있게.
- **추가 스크립트(EffectComposer)**: CDN r128 호환 버전을 고정하고, `tests/vendor`에 복사해 픽스처 라우트 확장. 로딩 실패 시 후처리 없이 계속 동작(폴백).
- **모바일 성능을 이 환경에서 못 잼**: 렌더 정보 수치와 적응형 강등을 안전장치로 두고, 실제 기기 점검 목록(아이폰 사파리, 중급 안드로이드)을 문서에 적는다. 이것은 사용자 확인이 필요하다.
- **그림자 맵 비용·떨림**: 범위를 플레이어 중심 스냅(텍셀 단위)으로 고정해 떨림을 막고, 캐스터를 거리 청크로 제한.
- **삼각형 예산**: 구름·새·글로우 판은 인스턴싱이라 삼각형이 작다. 도심 재설계의 110k 한도와 합쳐서 `zz-tris`로 항목별 측정한다.
- **500줄 제한**, 문서(`docs/tech/`)·`COORDINATION.md` 갱신, 마일스톤마다 커밋.

## 10. 검증
- `cd client && npx tsc` 무오류.
- `?gfx=desktop`, `?gfx=mobile` 두 프로필로 스폰 시야 `renderer.info`(삼각형·호출)가 프로필별 예산 이내.
- 픽셀 검사 E2E: 하늘 영역에 구름 픽셀이 있다(밝기 분산), PC에서 캐릭터 아래 그림자 픽셀이 더 어둡다, 밤 글로우 픽셀이 밝다, 비 날씨에 줄기 픽셀 존재.
- 프로필 스위치: 설정 변경이 즉시 반영되고 세이브·복원 된다. 적응형 강등이 인위적 지연(느린 프레임 주입)에서 동작한다.
- 기존 전체 E2E 통과(톤매핑 변경으로 색에 의존하는 픽셀 테스트는 조정).
- 스크린샷(`tests/out/gfx-*.png`): 낮·일몰·밤·비 × PC·모바일 8장을 나란히 육안 비교. 마지막에 실제 기기(모바일·PC)에서 사용자가 확인.

## 11. Codex 검토 제안 (2026-11-06)

사용자 요청에 따라 원문은 유지하고 이 파일 말미에 검토 의견을 추가했다. 현행 게임 코드와 로컬 `three@0.128.0` 소스를 대조했으며, 아래는 구현 전 보완 제안이다. P0는 선행 계약, P1은 효과별 품질·성능 보완이다. 그래픽 코드 자체는 이번 검토에서 변경하지 않았다.

### 11-1. 현황과 예산의 의미부터 맞추기 — P0

- 현재는 순수 정점색만 쓰는 상태가 아니다. `surface-detail.ts`의 공유 Lambert와16종 표면 무늬, `water-shader.ts`의 프레넬/태양 반짝임, 하늘 그라데이션·해 후광이 이미 있다. 새 효과는 이 경로에 합성해야 한다. [TEXTURES](../tech/TEXTURES.md)를 현황 기준에 추가한다.
- 최근 스폰 검수는 **93,446삼각형/393 calls**, 기존 스펙의 기준은95k다. PC110k는 새로운 목표 후보로 구분하고 기존 기준을 바꾸는 이유를 명시한다. 모바일60k/250calls는 효과를 끄는 것만으로 달성되지 않으므로 건물·지형·수목·군중의 어떤 LOD/가시거리를 줄이는지 예산표가 필요하다.
- 인스턴싱은 호출을 줄이지만 인스턴스 전체의 삼각형·그림자 패스·반투명 픽셀 비용을 없애지 않는다. “런타임 비용0인 AO”, “CSS 비용 거의 없음”은 추가 패스가 없다는 뜻과 실제 비용을 구분해서 표현한다. SwiftShader FPS는 실기기 성능 기준으로 쓰지 않는다.

### 11-2. 색 관리와 최종 출력 변환을 한 계약으로 정의하기 — P0

현재 `palette.rgb()`는 hex 값을 그대로0~1로 바꾸고, 기본 Lambert/Basic과 물의 커스텀 ShaderMaterial은 출력 경로가 다르다. `water-shader.ts`는 `gl_FragColor` 뒤 fog만 처리하므로 renderer에 ACES/sRGB를 켜도 기본 재질과 같은 변환이 자동으로 생기지 않는다.

- 정점색·일반 색 텍스처·CanvasTexture·물 uniform·하늘·안개의 입력 색 공간을 표로 정한다. 팔레트를 재조정하기 전에 입력을 선형으로 해석할지 변환할지부터 일관되게 결정한다. 수치 데이터인 packed detail/지형 ID 텍스처는 Linear로 유지한다.
- 직접 렌더와 Composer 양쪽에서 **선형 장면 계산 → 필요한 효과 합성 → 톤매핑/출력 인코딩을 최종1회 적용**하는 책임을 정한다. 재질에서 이미 변환한 결과를 마지막 패스가 다시 변환하거나, CopyShader만 거쳐 출력 변환을 누락하지 않게 한다. r128 기본 재질의 tone/encoding/fog 순서와 커스텀 셰이더를 실제로 대조해야 한다.
- RGBA8 기본 타깃을 그대로 쓸지, 지원되는 경우 HDR 타깃을 쓸지와 fallback을 정한다. 블룸의 밝기 임계값이 일반 흰 벽 대신 실제 발광면을 선택하게 해야 한다. 현재 `glowMat()`은 발광 강도 정보가 없는 Basic 정점색 재질이다.
- 검증 장면에는 밝은 벽·캐릭터 피부·네온·물·안개 경계를 함께 넣는다. 같은 상태의 직접 렌더/후처리 결과에서 색이 달라지는 이유를 설명할 수 있어야 한다. 기존 픽셀 테스트의 기준을 바꾸기 전에 실제 색 변화와 포화 영역을 확인한다.

### 11-3. 품질 선택·자동 감지·적응형 강등을 분리하기 — P0

- 우선순위를 **URL 강제값 → 저장된 수동 선택 → 자동 감지**로 명시한다. PC/모바일 기본 프로필과 자동/절전이라는 사용자 선택이 어떻게 연결되는지도 정한다. 미지원 기능은 강제 프로필에서도 안전하게 대체하고 사유를 진단에 남긴다.
- `TOUCH`는 입력/UI 판정이며 GPU 성능 지표가 아니다. 터치 노트북·고성능 태블릿·`deviceMemory` 미지원 브라우저를 고려한다. 품질 모듈이 `systems/input.ts`를 import하면 게임/UI 모듈까지 먼저 실행될 수 있으므로 감지 코드는 순수한 별도 모듈로 분리한다.
- 사용자 선호와 기기별 유효 설정을 나눈다. 자동 감지 결과나 일시적인 강등을 `S.gfx`의 사용자 선택으로 덮어쓰지 않는다. 기기 로컬 설정과 계정 동기화 범위도 구분한다. 세이브에 필드를 추가한다면 타입·기본값뿐 아니라 잘못된 enum/부분 객체의 정규화까지 포함한다.
- 적응형은 현재 loop의0.05초 제한 `raw`나 pause 시0이 되는 `dt` 대신 실제 RAF 간격/단조 시계로 판단한다. 숨은 탭, 초기 컴파일·업로드, 복귀·resize 직후는 측정에서 제외하고 강등 후 cooldown/재측정을 둔다. `?gfx=`로 고정한 검사에서는 적응형을 잠근다.
- `powerPreference`와 생성 시 antialias 같은 옵션은 단순 런타임 토글과 구분한다. 모든 프로필에 `high-performance`를 강제하는 정책이 절전 모드와 맞는지도 정한다.

### 11-4. 전체 프레임 패스와 픽셀/메모리 비용을 측정하기 — P0

r128 `WebGLRenderer`는 그림자 렌더 뒤 `info`를 초기화한다. Composer에서는 마지막 패스의 수치만 남을 수도 있다. 지금의 `renderer.info` 한 번 읽기만으로 새 효과 전체를 검증하면 그림자/반사 비용을 놓치거나 장면을 fullscreen quad 몇 개로 잘못 셀 수 있다.

- `info.autoReset=false`와 프레임 시작1회 reset 같은 계측 계약을 두고 주 장면·그림자·수면 반사·큐브맵·후처리를 별도로 집계한다. 주 장면의 기존95k 기준과 전체 프레임의 추가 패스 예산을 나눈다.
- r128 기본 UnrealBloom은 밝기 추출·다단계 블러·합성 등을 합쳐13회 fullscreen draw가 발생한다(화면 직접 출력 경로는 copy 추가). 따라서 “절반 해상도 블룸1개”를 단일 저비용 패스로 보지 않는다. CubeCamera 갱신도6회 렌더라는 비용을 포함한다.
- 타깃 크기는 `CSS 크기 × DPR × 렌더 배율 × 패스 배율`로 계산한다. “절반 해상도”가 폭/높이 각각 절반인지 명시하고 포맷·깊이·버퍼 수·MSAA를 포함한 RT 메모리 예산을 둔다. 셰이더/확장 지원을 확인한 뒤 HDR·반사·SSAO를 켠다.
- 큰 후광 판·구름·안개·비·CSS 오버레이에는 활성 수뿐 아니라 최대 화면 점유율·겹침·거리 감쇠를 정한다. 삼각형과 calls가 낮아도 픽셀을 여러 번 덮으면 느려질 수 있다. 실기기에서는 지속 프레임 시간과 장시간 실행 시 발열에 따른 저하도 기록한다.

### 11-5. 프레임 상태와 그래픽 자원의 수명을 중앙에서 관리하기 — P0

- 낮밤·날씨·태양 방향·노출·실내 어둠은 주 프레임에서1회 계산한 환경 snapshot으로 공유한다. `visualTint(dt)`는 새벽 타이머를 변경하므로 반사/큐브맵 패스에서 다시 호출하면 안 된다. 낮720초/밤240초 게임 규칙과 시각 보간을 분리해 유지한다.
- 주 화면뿐 아니라 폰 사진·전체 지도·검수 도구도 사용할 중앙 렌더 진입점 또는 명시적인 우회 규칙을 둔다. 테스트가 계속 `renderer.render()`를 직접 호출하면 실제 Composer 출력과 다른 화면을 검사할 수 있다.
- 각 효과에 `enable/update/resize/dispose/restore`와 소유 자원 목록을 둔다. 현재 resize는 renderer/camera만 갱신하므로 Composer·반사·SSAO 타깃과 DPR/렌더 배율도 함께 반영해야 한다. 공유 `lowMat`, `glowMat`, 표면 팩을 기능 해제 때 버리지 않는다.
- context lost 중에는 렌더/적응형 판정을 멈추고 복구 정책을 정한다. PC↔모바일 반복 전환과 해상도 변경 후 타깃·geometry·texture 수가 누적되지 않는지 확인한다.
- 번개·피격·컷신의 flash는 별도 채널이나 우선순위/취소 규칙으로 합성한다. 현재 `hud.flash()`는 같은 `#flash`를 timeout으로 지우므로 효과들이 서로 지울 수 있다. 강한 번쩍임·카메라 물방울은 끌 수 있게 하고 입자/번개의 시간·seed를 검사에서 고정한다.

### 11-6. 그림자에 필요한 형상·방향·바닥 층을 명시하기 — P1

- 그림자 카메라는 light와 target을 같은 태양 방향을 유지하며 이동시키고 텍셀 기준으로 스냅한다. 현재 `syncWater()`는 `sun.position.normalize()`를 태양 방향으로 사용하므로 광원을 플레이어와 함께 이동시키면 물의 하이라이트 방향이 달라질 수 있다. 환경 snapshot의 공통 방향 벡터를 사용하도록 계약을 바꾼다.
- 주 카메라에 안 보이더라도 그림자를 던지는 건물/나무가 있을 수 있다. caster 범위와 렌더 LOD 범위를 나누고, 큰 병합 건물의 proxy/청크 정책을 정한다. 저고도 태양에서의 길어진 그림자·bias·해상도와 태양/달 전환도 별도 장면으로 확인한다.
- 바람의 정점 변형은 beauty의 `onBeforeCompile`만 바꾸면 depth/distance 그림자에 자동 반영되지 않는다. 필요한 `customDepthMaterial`/`customDistanceMaterial`에 같은 변형·시간을 적용하고 최대 흔들림만큼 컬링 경계를 확장한다. 표면 질감 패치와의 합성 순서·program cache key도 공유한다.
- 모바일 접촉 그림자는 단순 y=0 판이 아니라 실제 발밑 지형/램프/교량/실내 바닥 층에 맞춘다. 경사·점프·공중/수영·차량 탑승 때 위치/농도를 조정하고 z-fighting, 옆 층 투영, AO와 겹친 과도한 어두워짐을 검사한다.
- 반전 껍질 외곽선은 사각 머리/팔다리의 모서리 벌어짐과 관절, 의상·모자·눈동자 동작을 확인한다. 두께0.02가 로컬/월드 중 어떤 단위인지 정하고, 실제 축척 재설계 및 카메라 거리 변화에서 비교한다.

### 11-7. 반사와 차량 재질의 적용 범위를 제한하기 — P1

- 바다와 두 호수는 높이가 다르므로 수면별 캡처 평면이 필요하다. 프레임당 활성 캡처 수·해상도·갱신 빈도를 정하고 반사 패스에서는 반사 수면들을 제외하는 재진입 guard를 둔다. 그림자 중복 갱신을 억제하고 타깃·viewport·visibility·clipping 상태를 끝에 복원한다.
- 하늘과 기존 거리 visibility는 주 카메라 기준이다. 반사 카메라에서도 필요한 하늘/건물이 빠지지 않는지 검사하고, 카메라별 준비 작업이 낮밤 시간을 다시 진행시키지 않게 한다. 반사 경계·수면 아래 clip·물가 투명도·해안 거품을 함께 확인한다.
- 현재 차량은 차체·유리·타이어를 하나의 solid 메시로 병합하고 `lowMat()`도 다른 물체와 공유한다. 차량 전용 재질과 표면 역할/반사 마스크를 설계한다. 전역 `lowMat`에 envMap을 달아 캐릭터·도로·타이어까지 반사시키지 않는다. r128에서는 `scene.environment`를 지정하는 것만으로 Lambert까지 자동 적용되지 않는다.
- 큐브맵은 가능하면 하늘 전용 장면에서 만들고 시간대/날씨가 충분히 바뀔 때만 갱신한다. 실제 위치 실내의 유리창은 불투명 창문 LOD와 투명 창문을 분리하되 정렬·겹침·추가 호출 비용을 측정한다. 반사나 블룸이 가짜 조명만 보여주는 경우와 실제 표면을 밝히는 광원은 구분한다.

### 11-8. AO·바람·발광은 도시 컴파일러의 의미 데이터를 소비하기 — P0

- 도시 JSON 빌드 결과에 안정적인 객체 ID와 표면 역할, 발광 위치/역할, 실내 영역·문 transform, shadow proxy와 수면 정보를 제공한다. 그래픽 계층은 같은 구조물의 표현을 선택하고, 품질 변경이 건물 ID·배치·충돌·출입 가능 여부를 바꾸지 않게 한다. 가로등마다 그래픽 쪽에서 별도 좌표를 다시 작성하지 않는다.
- 일반 `mergePlaced()`는 캐릭터·차량·실내·소품에도 쓰인다. 여기에 무조건 AO를 곱하지 말고 도시 빌드/정적 모델 생성의 명시적 단계로 둔다. 원색과 AO 또는 bake 버전을 분리해 재병합/재빌드 때 누적해서 어두워지지 않게 한다.
- 모서리 정점 몇 개뿐인 큰 벽은 접촉 AO를 넣으면 면 전체가 어두워질 수 있다. 필요한 정점 분할·모델 자체 AO·지면 접촉 표현을 비교하고, 지오메트리/메모리 증가와 굽기 시간을 측정한다. 발광면에는 같은 AO를 무조건 적용하지 않는다. 이웃 구역을 수정했을 때 갱신할 AO 영향 범위도 정의한다.
- 공유 셰이더에 질감·바람·구름 그림자·젖음 기능을 추가할 때 callback을 서로 덮어쓰지 않게 한다. 기능별 패치 순서, uniform 소유, cache key와 지원 sampler/varying 예산을 정한다. 실내 표면까지 구름 그림자나 비 젖음이 적용되지 않도록 표면 역할을 사용한다.

### 11-9. 하늘·밤·날씨는 수량보다 합성과 가독성을 먼저 정하기 — P1

- 카메라를 따라가는 배경 구름과 실제 산/호수 부근의 낮은 구름·안개를 구분한다. 현재 하늘은 depth를 무시하는 별도 순서를 사용하므로 태양/별이 구름을 뚫고 보이거나 구름이 지형 위를 덮는 문제가 없도록 깊이 검사·불투명/반투명 패스 순서를 설계한다. 인스턴스 내부가 개별 투명 정렬되지 않는 경우도 고려한다.
- 사과 행성 같은 중요한 목표의 시선 영역과 지평선/하늘/안개 색 경계를 확인한다. 최근 카메라는75° 위를 볼 수 있으므로 기존 하늘 주석의 좁은 시야를 기준으로 구름을 배치하지 않는다. 천정·구름 아래·고가 아래에서도 검수한다.
- 후광 판은 발광점에 붙고 벽/건물에 가려지며 거리에 따라 줄어들게 한다. 블룸이 일반 흰 표면과 HUD까지 과도하게 번지지 않게 한다. 헤드라이트2~4개의 선택은 거리뿐 아니라 화면 기여도와 교체 안정성을 고려하고 그림자 사용 여부를 따로 정한다.
- 비/튀김은 실제 바닥·수면·실내 여부를 읽는다. 실내·처마 아래로 비가 새거나 고가의 빗방울이 아래 도로까지 관통하지 않게 한다. 품질에 따른 비 입자 수 변경은 날씨/게임 규칙 변경과 분리한다.

### 11-10. r128 의존성·AA·지원 불가 경로를 구체화하기 — P0

- 현재는 UMD 전역 `THREE` 한 개다. 같은 r128의 `examples/js`를 추가한다면 Composer만이 아니라 Pass/Shader 등의 전체 의존 관계와 로딩 순서를 고정한다. `jsm`으로 바꾸면 별도 three 모듈 인스턴스가 섞이지 않도록 전체 import 경계를 정한다. 라이브러리 업그레이드는 효과 추가와 별도 작업으로 다룬다.
- 배포와 테스트가 같은 addon 파일을 쓰게 하고 로컬 경로·하위 경로 배포를 검증한다. addon이 실패해도 게임 초기화가 중단되지 않도록 직접 렌더 fallback을 둔다. 후처리 없는 경로도 최종 색 변환 계약을 지켜야 한다.
- `antialias:true`만으로 Composer 오프스크린 타깃까지 같은 AA를 얻는다고 가정하지 않는다. 지원되는 MSAA 또는 별도 AA 패스와 fallback을 정하고 비용을 포함한다. SSAO의 자체 beauty/normal 렌더와 기존 RenderPass의 중복도 확인한다. 물의 discard와 바람 변형이 normal/depth 보조 패스에서도 맞는지 검사한다.

### 11-11. 작은 기준 장면·효과별 완료 조건·파일 소유를 먼저 고정하기 — P0

권장 순서는 **품질/계측/출력 경로 → 색 관리 기준 장면 → 구름·AO·기본 밤 표현 → 그림자 → 반사/블룸 개별 측정 → 날씨·선택 SSAO**다. 각 단계는 전체 그래픽 목표를 줄이는 것이 아니라 효과를 하나씩 추가해 비용과 화질 변화의 원인을 확인하기 위한 순서다.

- 같은 카메라·시간·날씨·seed·노출에서 효과 OFF/ON을 비교한다. 단순 밝기 분산은 기존 하늘 그라데이션/별도 통과시키므로 효과별 ROI와 대조 장면을 정한다. 최종 출력 경로를 검사하고, CSS 플래시/물방울은 canvas 픽셀 검사와 분리한다. 자동 강등·번개·시간 진행은 검사에서 제어한다.
- 낮·일몰·밤·비의8장 외에 실제 위치 실내↔실외 전환, 물가, 경사면/교량 위 접촉 그림자, 흔들리는 나무, 주차장 헤드라이트, 품질 반복 전환·resize·context 복구를 추가한다. 실기기 성능 확인 전에는 PC/모바일 목표 달성을 확정으로 기록하지 않는다.
- `sky.ts`는 G0/G1/G2가 함께 편집하지 않도록 한 담당이 환경 상태/광원을 소유한다. GFX의 중앙 렌더·품질/타깃 수명 담당도 한 명으로 지정한다. 도시 빌드 담당은 AO/소품 의미 데이터를 출력하고 G2/G4/G5는 이를 소비한다.
- `lowpoly/merge.ts`·`surface-detail.ts`·차량 렌더·`phone-apps.ts`·`loop.ts`는 도시/조작 작업과 공유되므로 포괄 소유 대신 파일별 편집자와 API를 먼저 정한다. 공유 셰이더 패치는 한 담당이 통합하고 각 효과 담당은 독립 모듈을 제공하는 방식이 안전하다.
