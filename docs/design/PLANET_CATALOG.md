# 행성 도감 카탈로그 — 80종 상세 명세

[CONTENT_PLAN.md](CONTENT_PLAN.md) 2장의 구역별 행성 목록을 **구현 가능한 행(row) 단위**로 풀어 쓴 문서다. 스토리는 [STORY.md](STORY.md), 교육 범위·출제 금지선은 [CURRICULUM.md](../curriculum/CURRICULUM.md)가 기준이다.
초안이며, 확정된 행만 `client/src/data/planets-more.ts`로 옮긴다.

> 표기: **⚠** = 사실 확인 필요(천체 수치·발견 연도·분류·"추정" 서술). 이 문서는 확인되지 않은 수치를 **적지 않았다**. 질량 M·반지름 R·가격은 데이터 투입 때 NASA Planetary Fact Sheet / Exoplanet Archive로 채운다(6장). ⚠ 행의 설명도 투입 전에 한 번 더 검수한다.

## 0. 먼저 알아둘 점 (코드·기획서와의 차이)

- **기존 행성은 26종이 아니라 25종**이다(`planets.ts`의 `DB_BASE` 25행, id 0~24). 그래서 신규는 **55종(id 25~79)**, 합계 80. **25종 확정(코드 기준)** — 달은 신규(id 25)로 센다.
- (해소됨: CONTENT_PLAN에서 S12의 중복 항목을 삭제했다) 기획서 S12에는 `프록시마 센타우리`가 S6와 **중복** 기재되어 있었다. 이 문서는 S6에만 두어 S12는 6종, 전체 **80종(중복 없음)**.
- 현행 `sectors.ts`는 임시 12구역(solar·exo·gargantua·alpha·belt·kuiper·…)이다. 이 문서의 S1~S12 풀 배치는 12구역 재편(M5, CONTENT_PLAN 2장 매핑표) 후 반영된다.
- 사과 행성·삼성 행성은 **80종 밖의 특수 행성**(5장, id 80~83 예약).
- 기존 id의 등급 t·가격은 **바꾸지 않는다**(세이브 키·경제 영향). 아래 t는 기존 행은 현행 값 그대로, 신규는 제안값.
- 수치 열(M, R, 가격)은 표에 넣지 않았다. 기존 25종은 `planets.ts` 값을 유지한다.

## 3. 외형 제작 규칙 (절차적 텍스처 파라미터 템플릿)

현행은 `c1`(밝은 쪽)·`c2`(어두운 쪽) 두 색과 `fx` 플래그(`glow` `band` `ring` `egg` `star`)로 그린다. 이를 **원형(archetype) + 파라미터 객체**로 확장하면 80종을 색표만 바꿔 일관되게 만들 수 있다. (코드 변경은 별도 작업. 아래는 데이터 규격 제안.)

### 3.1 공통 템플릿 (`look` — DbRow 확장이 아니라 별도 맵 권장)
현행 `DbRow` 는 10칸 튜플(`[이름, 분류, M, R, 등급, 가격, c1, c2, 설명, fx?]`, `core/types.ts`)이라 객체형 `look` 을 11번째 칸에 넣으면 `DB_BASE`/`DB_MORE` 25+55행의 튜플 형식이 깨진다. `LOOKS: Record<number /*id*/, Look>` 처럼 id 키 맵을 `data/planet-looks.ts` 에 두는 편이 안전하다(DbRow·세이브 id 불변 규칙과도 맞음).

```
look: {
  arch: 'ROCK'|'TERR'|'CLOUD'|'GAS'|'ICEG'|'ICE'|'LAVA'|'MOON'|'STAR'|'NEB'|'DEAD'|'BH'|'FICT',
  c: [c1, c2, accent?],        // 밝은 면 / 어두운 면 / 강조(선택)
  noise: {oct: 3~5, scale: 1~4, warp: 0~0.6},   // 표면 질감
  bands: {n: 0~14, contrast: 0~1, tilt: 0~°},   // 줄무늬
  craters: {density: 0~1, maxR: 0.05~0.3},
  clouds: {cover: 0~1, speed: 0~1},
  crack: 0~1, lava: 0~1, spots: {n, color, size},
  ring: {inner, outer, tilt, alpha},            // 없으면 null
  glow: {color, power}, atmo: {color, thick},
  shape: {egg: 0~1, irreg: 0~1, aspect: [x,y,z]},
  tidal: 0|1,                                    // 조석 고정: 낮/밤 색 분리
  seed: id                                       // 같은 행성은 항상 같은 모양
}
```

### 3.3 색·크기·식별 규칙
1. **c1은 c2보다 밝게**(명도 차 ≥ 25%). 같은 구역 안 같은 원형은 색상환 hue 차 **30° 이상**.
2. **색만으로 구분하지 않는다**(STORY 접근성): 행성마다 **한 가지 실루엣 단서**(고리·달걀·줄무늬 수·꼬리·반점·땅콩 모양)를 필수로 둔다. 표의 "특징"이 곧 그 단서.
3. 크기는 R(지구 반경 기준) 로그 스케일로 보이는 크기를 정하되 **너무 작으면 손으로 집을 수 있게 최소 크기 보장**(위성·소행성은 R 무관하게 하한 적용). 정확한 비율은 R에서 계산하되 도감 화면에서만 "실제 크기 비교"를 보여 준다.
4. 위성은 **모행성과 한 쌍으로 보이는 연출**(작은 위성 궤도 표시)을 선택으로 둔다. 성운·블랙홀·항성은 **구 + 입자 후광**으로 표현하고 둥지 `kind`는 따로 구분하지 않는다(확정).
5. 사실로 알려진 모양은 반영하되 **세부 지형까지 지어내지 않는다**(표의 ⚠ 항목은 검수 전에 "그럴듯한 대표 색/모양"으로만).
6. 한 행성 텍스처 생성 예산: 256×128 캔버스 1장, 합성 2패스 이내(저사양 보호). 같은 seed → 같은 결과.

## 4. 돌연변이 · 희귀 변종 규칙

현행: `MUT = 일반(×1) / 고온 ×2 / 거대 ×3`, 확률 `MUT_CHANCE = [거대 0.03, 고온 0.12]`(누적 판정). 이를 보존하고 **외형만 변하는 변종**을 추가한다.

| 변종 | 가격·수익 배율 | 확률(제안) | 외형 변화 | 허용 대상 |
|---|---|---|---|---|
| 일반 | ×1 | 나머지 | 기본 | 전체 |
| 고온 (기존) | ×2 | 12%(현행 누적 판정 `0.97 × 0.12` ≈ **11.64%**) | c1·c2를 주황·붉은색쪽으로 시프트, 용암 균열 glow | 표의 "변:고온" 행성 |
| 거대 (기존) | ×3 | 3% | 모델 크기 ×1.3, 줄무늬 늘림 | "변:거대" 행성 |
| 얼음 (신규) | ×1.5 | 6% | 푸른 흰색 시프트, 서리 crack 추가 | "변:얼음" 행성 |
| 오로라 (신규) | ×2.5 | 1.5% | 극지 초록·보라 띠 애니메이션 | "변:오로라" 행성 |
| 황금 (신규) | ×5 | 0.2% | 금속 광택 + 반짝임 입자, 도감 별도 칸 | "변:황금" 행성 |

규칙:
1. **한 개체에 변종은 최대 1개**. 판정 순서는 희귀한 것부터(황금 → 거대 → 오로라 → 고온 → 얼음) — 기존 누적 판정과 호환되게 구현.
2. **변이 불가**: 항성(STAR), 블랙홀(BH), 사과 행성, 삼성 행성. 항성·블랙홀은 크기·밝기 변화가 세계관과 충돌하기 때문.
3. 위 변종 5종·확률·배율을 **확정**한다(황금 도감 별도 칸 보상 포함). 단 배율은 가격 재설계 때 재조정할 수 있고, 확률 합이 구역 난이도를 깨지 않는지 시뮬레이션으로 한 번 검증한다(**보수안 표시**: 고등급일수록 변종 확률을 절반으로 낮추는 안은 시뮬레이션 결과를 보고 적용 여부 결정).
4. **도감 규칙**: 도감 칸은 행성별 1개 + 변종별 "발견 표시" 칸. 변종까지 모은 행성은 업적 대상. 황금 변종은 표에서 "변:황금"이 붙은 **8종**(이토카와·베누·핼리 혜성·원시 행성 원반·게성운·중성자별·할렐루야 산·강착원반 파편)만 가능하므로 장기 목표는 "황금 8종 완성"이다(80종 전부는 불가능).
5. 변종은 표의 `look` 와 별개로 **셰이더 후처리(색 시프트 + 오버레이)** 로만 만든다 → 80종 × 변종 5 = 400 텍스처를 따로 만들지 않는다.
6. 교육 연결: 변종 이름의 과학적 설명은 쓰지 않는다(재미 요소). 퀴즈 출제 소재는 일반 개체 기준 사실만.
7. **허용 대상 = 표의 "변:" 표기뿐**: 80행 중 고온 14 · 거대 12 · 오로라 12 · 얼음 10 · 황금 8 = 56종이 변종 1개를 가지고, 나머지 24종("변없음" 8 + 표기 없음 16: 달·포보스·데이모스·세레스·베스타·칼리스토·아말테아 등)은 변종이 없다. 현행 `newPlanet`(`core/state.ts`)은 **모든 행성**에 거대 3%·고온 12%를 적용하므로 `Planet`/`DbRow` 에 허용 변종 필드(`mutKind?: 'hot'|'giant'|'ice'|'aurora'|'gold'`)를 추가해야 한다. 이 규칙의 평균 변이 배수는 약 1.038 로 ECONOMY 2.4 의 가정(1.176)보다 낮다(보유 수익 약 −12%).
8. **`MUT` 인덱스 호환**: `Owned.mut`(세이브)는 현행 `MUT = ['', 고온 ×2, 거대 ×3]` 의 인덱스(0·1·2)다. 새 변종은 **뒤에만 추가**한다 — 3 = 얼음 ×1.5 · 4 = 오로라 ×2.5 · 5 = 황금 ×5. 순서를 바꾸면 기존 세이브의 고온/거대 개체가 바뀐다. 또 `mul(o)` 와 판매가 계산이 `MUT[o.mut][1]` 를 읽으므로 같은 배열에 넣는다.

## 6. 데이터 투입 작업 분담안

**공통 규칙**
- 행 추가는 **`planets-more.ts`의 `DB_MORE` 끝**에만, **id 순서 = 배열 순서**. 병렬 작업은 파일 충돌을 피하려고 **조각 파일**(`planets-more-a.ts` … `-f.ts`, 각 `DbRow[]`)을 따로 만들고, 마지막에 통합자가 `DB_MORE = [...A, ...B, ...F]`로 id 순서대로 합친다. 조각 안 행의 id 구간이 겹치지 않아야 한다.
- 행 형식: `[이름, 분류(0 실제/1 인터스텔라/2 아바타), M(M⊕), R(R⊕), t, 가격, c1, c2, 설명, fx]`. 이 문서의 외형·설명·t를 그대로 옮긴다.
- **M, R은 NASA 값으로**. ⚠ 행(총 52행)은 확인 못 하면 `// TODO 검증` 주석을 달고 값은 추정 표기, 설명은 "~로 알려져 있다/추정" 수준으로 완화한다. 확인 없이 단정하지 않는다(CURRICULUM 7.3).
- 가격 열: ECONOMY 8.2 #1 로 **DB 가격 열은 무시**되고 `planets.ts` 가 `ZONE_MUL[구역] × TIER_MUL[t]` 로 계산한다(구역 소속은 `sectors.ts` 풀에서 얻음). 따라서 신규 행의 가격 칸은 같은 t 의 기존 행성 가격대 안의 **임시값**이며, 구역 풀에 속하지 않으면 `price` 가 정해지지 않으므로 풀 반영(작업 G)이 먼저다.
- **풀 필터 주의**: 현행 `sectors.ts` 의 `exo`·`gargantua`·`alpha` 풀은 `grp`(분류 열) 필터(`'실제' && !SOLAR` / `'인터스텔라'` / `'아바타'`)라, 분류 0(실제)인 신규 행 55종 중 대부분이 풀 재편 전에는 전부 `exo` 로 흘러간다 → 행 추가와 `ids(...)` 풀 재편을 같은 변경으로 묶는다.
