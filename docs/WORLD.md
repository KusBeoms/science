# 월드 설계 — 도시 허브 + 이어진 대륙 + 로우폴리
> **상태: 제안 초안(2026-11-04) + 사용자 승인 일부.** 사용자가 확정한 것은 **① GTA 같은 오픈월드 감성의 도시 허브 + 이어진 대륙(구역이 지형으로 걸어서 이어짐, 이동수단은 속도·허공 횡단 보조), ② 로우폴리 그래픽(현재는 블록형), ③ W1 범위 승인됨(사용자), ④ 대륙 규모(약 740×1050u) 승인됨(사용자)** 이다. 아래의 좌표·수치·이름·시스템 구성 중 나머지는 **AI 제안**이며 사용자 승인 전에는 "확정"이 아니다(10장 열린 질문). 행성 모양(플랫 이코스피어 여부)은 "나중에 정하자"로 **보류**(10장 #10).
> 근거: [HANDOFF.md](HANDOFF.md) 2.1(사용자 원문 비전: 오픈월드·집 구매·시작 애니메이션·외부 캐릭터·10시간+), 4.3 갭 A1~A7. 코드 기준: `client/src/render/{world,sectors,characters,gear,deco,textures}.ts`, `core/{geometry,layout,progress}.ts`, `data/sectors.ts`, `systems/move.ts` (직접 읽음).
> 좌표계는 기존 그대로: x = 동(+), z = 남(+), y = 위. 길이 단위 u(유닛). 캐릭터 키 ≈ 3.6u.

## 1. 월드 개요 · 설계 원칙 · 성능 예산

### 1.1 한 장 요약
| 항목 | 현재(코드) | 제안 |
|---|---|---|
| 허브 | 44×44 초록 체크 타일 + 받침대 + 노점 1 + 점원 1 | **도시 300×300** (기지는 도시 한가운데 그대로 (0,0)) |
| 섹터 | 정사각형 평평한 색 타일 12개, 사이는 **허공** | **한 덩어리 대륙** 위의 분지(盆地) 12개. 사이는 통로(pass). 허공은 **해협 2곳 + 단애 3곳**뿐 |
| 지면 | `y=0` 고정, `onGround` = 사각형 합집합 | **높이 지도** `groundH(x,z)` (언덕·능선·절벽·해안) |
| 그래픽 | `BoxGeometry` 블록 + 체크 텍스처 | **로우폴리 플랫 셰이딩**, 팔레트 정점색, 텍스처 최소 |
| 대륙 크기 | 섹터 사이 허공 포함 약 560×900(좌표상 바운딩) | **약 740×1050u (육지 ≈ 5.0×10⁵u²)**, 걸어서 도시→S12 문까지 약 2,100u(달리기 ≈ 90초) |

- 이동 시간은 의도적으로 짧다. CONTENT_PLAN 0장: 10시간은 **맵 크기가 아니라** 진행 곡선·할 거리·장비·이야기로 채운다(이동 총 0.5h). 대륙의 역할은 "걷는 맛 + 시선 + 소속감"이지 시간 늘리기가 아니다.

### 1.2 설계 원칙
1. **무문자**(STORY 2장): 간판·표지·이정표는 **아이콘/픽토그램/점 개수**. 도시와 지형에 한글 문장을 `label()` 로 박지 않는다(기존 섹터 이름표 `"N단계 · 이름"`은 아이콘+점 N개로 교체 — 9장 충돌 목록).
2. **시선 유도**: 플레이어는 항상 **사과 행성**을 하늘에서 볼 수 있다(3.4). 구역 경계·목표는 지형과 색으로 읽힌다(능선·안개·문).
3. **걸어서 이어짐이 기본, 허공은 예외**: 이동수단은 "더 빠르게 / 지름길 / 허공 횡단"을 보조한다. 필수 허공 횡단은 **S5→S6 해협 하나**(소형 우주선, CONTENT_PLAN 3장·GAMEPLAY 1.1과 일치).
4. **해금 벽은 풍경으로**: 잠긴 구역은 투명 사각형 벽이 아니라 **능선 + 안개 + 문**으로 보인다. 판정은 기존 `blockedAt`(잠긴 사각형)을 그대로 쓴다(우주선도 못 넘음, GAMEPLAY 1.1 유지).
5. **데이터 주도 + 코드 생성**: 지형·건물·소품·캐릭터는 **파라미터 + 시드**로 코드가 만든다(에셋 파일 0개, 번들러 없음, three.js r128 유지). 모델링 파일/glTF 로더 도입 안 함.
6. **스트리밍 우선**: 만든 것을 전부 항상 그리지 않는다. 지형 타일·섹터 청크·도시 블록이 거리 기준으로 생성/해제(7장).
7. **기존 세이브 불변**: 섹터 id·행성 id·`S.base` 키 불변(8.1 호환 절).

## 2. 대륙 지도

### 2.1 구성 원칙
- **도시(H)** 가 중앙, 섹터 12개가 **시계 방향 나선**으로 바깥을 돈다: 북 → 동 → 남(해협) → 서 → 북서 → 북.
- 구역 사이는 **폭 40 × 길이 30~70의 통로**(능선이 갈라진 협곡 길). 통로 중앙에 문(아치)이 선다. 통로 밖 나머지 틈(≈30u)은 **단애(절벽)**: 점프팩 이상으로 건널 수 있는 짧은 허공 또는 막힌 산.
- 섹터 `center/size` 는 **판정용 바운딩 사각형**(기존 `inSector`·`sectorDist`·`zoneAt` 유지). 실제 모양은 능선 둘레로 만든 분지(2.5).
- 최종 S12(알파 센타우리)는 시작 구역 S1의 **바로 북쪽 산 너머**(40u 단애)에 둔다 → 첫 구역에서 보이는 산 너머가 마지막 목적지(복선, 이동수단으로는 지름길).

### 2.4 해금 벽의 시각적 표현
구역마다 **경계 유형**이 다르다. 잠김/풀림에 따라 아래 4가지 요소가 바뀐다(잠금 판정은 기존 `locked(i)` / `isNext(i)`).

| 상태 | 문(아치) | 둘레 | 멀리서 보임(7.4) |
|---|---|---|---|
| 잠김·다음 차례(`isNext`) | 붉은 장벽 + 맥동 화살표(기존 `panel` 확장), 문 앞 시험 상호작용 | 능선 + **안개 기둥** | 분지가 안개색으로 가려짐 |
| 잠김·아직 멂 | 회색 셔터(닫힘) | 능선 + 짙은 안개 | 동일 |
| 풀림 | 아치 개방, 초록 링 발광 | 안개가 **걷히는 연출 3초**(첫 해금 시), 능선은 영구 유지 | 분지 색이 드러남 |

구역별 경계 장식(잠금 표현의 개성, `SectorTerrain.edge`):

| S | 문 양식 | 둘레 장식 |
|---|---|---|
| S1 `solar` | 석조 아치 | 낮은 암릉 |
| S2 `belt` | 바위 아치(떠다니는 바위로 만든 문) | 협곡 절벽 |
| S3 `jovian` | 구름 기둥 문 | 줄무늬 폭풍벽(스프라이트 링) |
| S4 `giants` | 얼음 창살문 | 빙벽 |
| S5 `kuiper` | 어두운 강철문 | 안개 + 얼음 결정 |
| S6 `reddwarf` | **부두 닻문**(해협 건너 도착한 곳) | 석양빛 절벽 |
| S7 `exo` | 쌍둥이 태양 아치 | 키 큰 풀·능선 |
| S8 `hotjup` | 방열 셔터 | 아지랑이 벽(왜곡 셰이더 대신 흔들리는 반투명 띠) |
| S9 `nebula` | 가스 커튼(문 없음, 안개가 문) | 짙은 보라 안개 |
| S10 `supernova` | 결정 파편 문 | 부유 결정벽 |
| S11 `gargantua` | 렌즈형 링 문 | 중력 왜곡 띠(느리게 일렁이는 링) |
| S12 `alpha` | 덩굴 문 | 발광 덩굴벽 |
- 풀린 구역의 능선은 **걷는 사람에게 정상 지형**(경사 > 45° 구간은 막힘, `walkable`). 능선 위를 넘는 것은 점프팩/우주선의 영역(지름길).

### 2.6 `Sector` 타입 확장 (하위 호환)
`center`, `size`, `gate`, `requires`, `floor`, `rim` 등 **기존 필드는 모두 유지**. 새 필드는 전부 **선택**이라 없으면 지금처럼 평평한 체크 타일로 동작한다(단계적 이행 가능).

### 3.4 사과 행성 시선 축
- 사과는 **하늘 천체**다(카메라에 붙은 스카이 객체, 시차 없음, 안개 무시, `renderOrder −1`, `depthWrite false`). 방위 **정북(−z)**, 고도 17°, 각지름 약 7°.
- `SPAWN (0,17)` 에서 카메라 기본 `yaw 0` 이 정북이므로 **게임 시작 시 사과 대로 끝 위에 사과가 자동으로 정면에 걸린다**(C01 첫눈에 반함과 일치, UX_CUTSCENE C01 카메라가 같은 객체를 쓴다).
- **시선 규칙**(코드 검사 함수 `checkSightAxis()` 로 디버그 시 검증): 도시/구역에서 방위 ±8°, 고도 8~30° 범위에 어떤 정적 물체의 윤곽도 들어오지 않는다. 구역 능선은 `ridge.h / 거리 < tan 10°` 이하(예: 거리 300에서 ≤ 53, 실제 ≤ 30).
- 엔딩 후: `S.story.ended` 이면 사과 객체를 **금빛 점선 윤곽(빈 하늘)** 으로 교체(STORY 6장). 주거 지구 집 창문에서도 같은 하늘이 보인다.
- 사과 행성에는 별도의 월드 장치를 붙이지 않는다. 주인공이 "어디서 파는지 모른다"는 설정은 컷신 C01/4-1의 말풍선(🔍❓)으로만 표현한다(월드 상시 표시 없음).

### 3.5 기지 · 암시장 · 거래의 선 · 포탈
- **기지**: 지금의 받침대·포탈 패드·상점 노점이 (0,0) 부지 안에 그대로 있다. 이행기엔 상점은 부지 안(`SHOP_AT`) 유지, W2에서 상점가로 옮기고 부지 안에는 **판매 부스**만 남긴다(상수 `SHOP_AT` 변경 1줄 + 점원 이동).
- **암시장**(STORY 5.3, B3): 암시장 골목 중앙 광장(−100,0)에 상인 부스. 행성을 들고 가서 판매(지금은 기지 슬롯에서 F). 두 위치 병행 가능(기지 슬롯 F 유지 + 부스는 "더 비싸게 팔기"는 ECONOMY 결정).
- **거래의 선**(STORY 5.3): 제안 — **도시 외곽 경계를 따라 금빛 선**(바닥 인레이 + 낮은 금색 기둥 띠). 도시 전체가 안전지대라 구역 추격형 수호자는 선을 못 넘고, 위장 수호신은 도시 안에서 구경만 한다(잡지 않음). STORY의 "암시장·기지·포탈 패드"는 이 안의 부분집합이라 충돌하지 않지만 문서 문구 수정 필요(9장).
- **포탈**: `HUB_PAD (15,−13)` 은 W2에서 항구·우주항 포탈 허브로 이전 후보(상수 1줄). 섹터 포탈 패드(`padPos`)는 문 안쪽 8u 지점 그대로. 허브 패드는 항상 보이고 `S.portals` 규칙 불변.

### 4.3 인테리어: **같은 씬의 포켓 방식**(제안, 별도 씬 비추천)
| 방식 | 장점 | 단점 | 판단 |

- 바닥 판정: 실내는 `groundH` 대신 평면 `y=0` 사각형(`interiorBounds`)만 허용(벽 안쪽 이동 제한 = 사각형 클램프, 가구는 슬롯 크기 원형 콜라이더).
- 카메라: 기존 오빗 카메라 유지, 실내에서는 `camDist` 4~12로 제한, 카메라 쪽을 향한 벽 1~2면 숨김(법선·시선 내적 > 0.3, 매 프레임 4회 비교).
- 실내 보호: `paused()`가 아님(돌아다닐 수 있음). 수호신·수배·혜성·라이벌 침입 억제(`G.curZone === −2`일 때 위험 시스템 `update` 건너뜀 — 각 시스템이 이 값을 보도록 훅 필요, 8장 W4).

### 4.4 가구·꾸미기
- 슬롯 격자식(자유 배치 아님 → 충돌·세이브 단순). 슬롯당 아이템 1개, 회전 4단계(0~3).
- 카탈로그 24종(아이콘 카드로 선택, 글 최소): 침대·소파·탁자·의자·책장·카펫·식물·램프·TV·수족관·망원경·트로피장 …, 그리고 **행성 전시대**: 도감/기지의 행성을 집에 진열(`S.dex` 읽기 전용, 기존 `makePlanet` 재사용) — "훔친 행성 자랑"이 집의 정체성. 벽: 그림·깃발·창(사과 그림 id 고정 1).
- 가구 가격은 ECONOMY가 정함(제안: 2k~60k, 집 가격 대비 합 ≤ 10%).
- 모든 가구는 6장 프리미티브로 코드 생성(각 20~120 tris). 실내 총 삼각형 ≤ 12k.

### 4.5 세이브 스키마 (희소 맵, 수 KB 이내)
```ts
S.home = {
  own: { tent: 1, cabin: 1 },                 // 집 종류 id → 1
  put: { 'tent.0': 3, 'cabin.5': 12 },        // `${집}.${슬롯}` → 가구 id (비어 있으면 키 없음)
  rot: { 'cabin.5': 2 },                      // 회전 0~3 (0이면 생략)
  skin: { cabin: 2 },                         // 벽/바닥 스킨 id (선택)
};
```
- `defaults()`에 `home: {own:{},put:{},rot:{},skin:{}}`. 구세이브는 필드 없으면 기본값으로 채워지므로 **버전 상승 불필요**(CLIENT.md "구필드 의미를 바꿀 때만 SAVE_VER +1"). 단 v6(섹터 id 병합, 8.1)와 같은 릴리스에 묶는 것을 제안.
- 런타임 상태(현재 실내 여부)는 저장하지 않고 항상 **도시 스폰(또는 집 현관)** 에서 시작.

### 5.2 보행 경로 그래프
- `data/citygraph.ts`: 보도 모서리·교차로·광장 원주·골목 중심선·건물 문 앞을 **노드**(약 140)로, 인접을 **간선**(약 180, 양방향, 가중치=길이·구역 선호도)으로 정적 배열(`Float32Array` 좌표 + `Uint16Array` 인접)로 둔다. 도로 마스크와 같은 `roadMask` 를 근거로 생성 후 **코드 검증**(연결성·고립 노드 0, 건물 콜라이더와 비교차).
- 에이전트 상태: `{edge, t, speed(1.8~3.6u/s), arch(0~7), tint, phase, mood, bubble}`. 다음 간선 = 가중치 랜덤(직전 간선 U턴 금지). 상점·좌판 앞 노드에서 2~6초 멈춤(idle). 문 노드에서 나오거나 들어감(페이드).

### 5.3 렌더 (InstancedMesh · LOD)
- 아키타입 8종(체형 3 × 복장 변형), 정점색 + 인스턴스 색(`setColorAt`).
- **근거리(< 35u)**: 부위별 InstancedMesh 5개(몸통+머리 / 다리 L·R / 팔 L·R) — 걸음 애니메이션은 인스턴스 행렬로 각도만 갱신. **중거리(35~80u)**: 몸통만 가진 1개 InstancedMesh(포즈 없음). **80u 초과**: 그리지 않음. → 군중 전체 **드로우콜 6개**(수와 무관), 80명 × 약 150 tris = 12k.
- r128 `InstancedMesh`는 인스턴스별 컬링을 하지 않으므로 `frustumCulled=false` + 거리 선별로 `count` 를 줄여 그린다.
- 말풍선(😮 👀 😱 💰): 이모지 아틀라스 1장의 스프라이트 풀 6개(동시 최대 6, 가장 가까운 순).

### 5.4 스폰 / 디스폰
- 활성 구역: 플레이어가 도시 경계 +60 안에 있을 때만 시뮬(밖이면 정지·해제). 스폰은 초당 ≤ 2명, **문 노드 또는 시야 밖(카메라 전방 ±70° 밖) 40u 이상** 노드에서만. 디스폰은 거리 > 100 또는 시야 밖에서 문 노드 도착.
- 상한은 Q 단계별(1.3 표). 빈 곳은 구역별 목표 밀도로 채운다. 시드는 `floor(gameT/60)`로 외형만 안정(저장 안 함).

### 5.5 반응(글 없음 — 머리 위 이모지 + 시선/몸짓)
| 상황 | 반응 | 반경·쿨다운 |
|---|---|---|
| 행성을 든 채 접근 | 몸을 돌려 쳐다봄 + 👀 | 6u / 20초 |
| 플레이어 달리며 접근 | 한 걸음 비킴(옆 간선으로) + 😮 | 3u |

- **행인 위장 수호신과의 관계**: 위장체는 군중의 한 아키타입과 **같은 외형·같은 보행**을 쓰되 풀 디테일 객체로 분리되어 `crowd.claim(id)` 로 인스턴스를 빼앗아 간다. 단서(STORY 5.2): 눈이 0.15초 금빛으로 번쩍(5~8초 간격), 상점 앞 idle에서 **가만히 플레이어를 향해 있음**(다른 행인은 랜덤 방향). 도시는 거래의 선 안이라 닿아도 잡지 않는다. 수호신이 숨는 변신 대상으로 군중 아키타입·좌판 상자를 쓴다(5.1 시선 규칙은 B4 소관).

| **지형 원경** | 대륙 전체 32u 격자(약 1.7k tris) 메시 1개 | **항상** | 능선·해안·구역 색 | 동일 |
| **섹터 청크**(기존) | 섹터당 1개 | `sectorDist < LOAD(140)` / `> UNLOAD(180)`, 구역별 `terrain.load` 로 덮어씀 | 항성·궤도선·둥지 행성·문·수호자 (+ 바이옴 소품·랜드마크) | `render/sectors.ts` 확장(`G.chunks[i]` 계약 불변) |
| **도시 블록** | 60×60u 블록 25개 | 도시 반경 200 안이면 전부, 260 밖이면 해제. 프레임당 1블록 | 병합 건물 + 소품 + 창문 메시 | `render/city/` 신규 |
- 지형 타일은 높이 지도 격자에서 직접 정점 높이를 읽으므로 **타일 생성 ≈ 1ms 미만**. LOD 경계는 **스커트**(가장자리 정점을 2u 내림)로 틈 방지. 원경 메시는 근거리 타일 아래 0.4u에 깔아 z-파이팅을 피한다(`polygonOffset`).
- 원경 구역 표시: 구역마다 항성/랜드마크 **빛점**(`Points` 1개로 12개, `fog:false`)을 두어 700u 밖에서도 "저기에 뭔가 있다"가 보인다. 잠긴 구역은 원경 메시 색이 안개색(H1 "멀리 있는 섹터가 안 보임" 해소).
- `freeTree` 호환: 병합 메시 해제는 `geometry.dispose()` 만, 공유 재질은 `keep`(6.2).

### 7.2 높이 지도 굽기 (부팅 시 1회, ≤ 120ms)
- `bakeContinent()` (`core/terrain.ts`): 격자 4u 각 칸에서 ① **육지 마스크** = 도시 ∪ 섹터 사각형 ∪ 통로 − 해협/단애 − 해안 노이즈(가장자리 6u는 −6까지 경사) ② **높이** = 섹터 분지(`base + relief fbm`) + 능선 링(통로 개구 제외, 가장자리 부드럽게) + 도시 평지(경계 12u 블렌드) + 북서 언덕 + 성 부지 평탄화 + 도로 평탄화 ③ 정점색용 `slope`. 결과는 `Float32Array` 하나(≈190KB).
- 같은 함수 `roadMask(x,z)` 와 `cityGraph` 가 도로를 공유한다.

### 7.3 충돌 · 지면 높이 판정 (`onGround`/`blockedAt` 대체안)
공개 API(모든 이동수단·수배·하이스트 시스템이 쓰는 **계약**, `core/terrain.ts`):

```ts
groundH(x: number, z: number): number      // 이중선형 보간 높이. 허공이면 -Infinity
onGround(x, z): boolean                     // = groundH > -Infinity (호환 래퍼, geometry.ts 에서 재export)
walkable(x0, z0, y0, x1, z1): boolean       // 경사 한계(기본 한 걸음 상승 ≤ 1.4u / 경사 ≤ 45°) 검사
solidAt(x, z, r): boolean                   // 건물/큰 소품/가구 콜라이더(16u 해시 격자의 AABB·원)
blockedAt(x, z): boolean                    // 기존: 잠긴 섹터 사각형(비행에도 적용) — 불변
```
- `systems/move.ts` 변경은 작다: (a) 이동 후보 `(nx,nz)`가 `blockedAt || solidAt || !walkable` 이면 기존처럼 축 분리 슬라이드, (b) 바닥 판정을 `gnd = groundH(x,z)` 로 바꿔 `pos.y` 를 `gnd` 에 스냅(`y ≥ gnd` 유지, 내리막은 떨어짐 대신 즉시 스냅하되 낙차 > 2.5면 낙하), (c) 점프 조건 `pos.y <= gnd + 0.02`, (d) 낙하 리스폰 `y < −45` 유지, (e) `hover()`일 땐 `pos.y ≥ gnd + 1.5` 하한만 적용(우주선이 능선을 뚫지 않게).
- **절벽/허공**: 해협·단애는 `groundH = −∞` → 낙하. 해안 6u 경사가 "가장자리 경고"가 된다(시각: 가장자리 빛 띠).
- **건물**: 도시 건물은 AABB 콜라이더, 나무·바위는 작아서 비충돌(몸이 통과해도 무방, 큰 바위·랜드마크만 원형). 군중은 플레이어와 충돌 없음(비킴으로 처리).
- **카메라**: 지면 아래로 못 가게 `camera.y ≥ groundH(cam.x,cam.z) + 0.8` 클램프. 건물 속 카메라는 W2에서 반투명 처리 검토.
- **중력/섹터 환경**: `gravityNow()` 등 섹터 훅은 그대로(구역 판정 `zoneAt` 은 사각형).
- **고도 기준**: 비행 시스템(M2)은 절대 y가 아니라 `alt = pos.y − groundH` 를 쓴다(고도계·착륙 판정 공통).

**`loop.ts` 영향**: 추가 호출은 `streamTerrain(p)`·`skyUpdate(dt)` 2개(기존 `streamSectors` 직후)뿐이고 군중·낮밤은 `registerSystem`으로 붙여 공용 파일을 건드리지 않는다.
