## 1. 프로젝트 기본 정보

### 1.1 저장소 구조
```
science/
├─ CLAUDE.md              # 작업 규칙(아래 1.3)
├─ docker-compose.yml     # web(공개) + api. DB/Redis 컨테이너 없음
├─ client/                # TS 클라이언트  (src/, public/, tests/)
```

- 주요 진입점: `client/src/main.ts` → `systems/index.ts`(시스템·상호작용 등록) → `systems/loop.ts`(프레임 루프).
- 구조 상세·"새 기능 추가 레시피": [CLIENT.md](CLIENT.md). 서버: [SERVER.md](SERVER.md). 테스트: [TESTING.md](TESTING.md).

### 1.3 프로젝트 규칙 (CLAUDE.md + 사용자 지시)
- **코드 파일(ts, css) 1개당 ~400줄 권장, 최대 500줄**. HTML은 예외. 읽기 좋게 포맷(한 줄 압축 금지)하고 죽은 코드 금지.
- 작업 전 `docs/README.md` 읽기, 작업 후 **docs에 변경 반영**. 마일스톤 도달 시 간단히 **커밋**.
- CLAUDE.md는 상위 `../README.md`를 읽고 갱신하라고 하지만 **그 파일이 존재하지 않는다**(미해결, 6장).
- **docker-compose**: 공개 서비스에 라벨 `science26.public=true`, API 서비스에 `science26.api=true`. **DB·Redis 컨테이너는 넣지 않는다.** 플랫폼이 주입하는 `DATABASE_URL`, `REDIS_URL` 환경변수를 서버가 읽는다(없으면 인메모리 폴백).
- 배포 경로: 하위 경로(`/steal-an-planet/`)로 서빙될 수 있어 **정적 리소스·API는 상대 경로**여야 한다(최근 수정됨).
- 사용자는 **여러 에이전트 병렬 사용을 허용**했다. 병렬 작업 시 파일 소유권을 나눌 것(7장).

## 2. 사용자 비전과 대화에서 나온 요구 (원문 근거)

### 2.1 사용자가 직접 한 말 (가장 믿을 수 있는 기준)

**비전 (가장 최근 불만 포함)**
> "우리가 생각한 맵은 이거보다 훨씬 오픈월드하고 집도 살수있고 완전 GTA같은감성을 원하고 시작하면 애니메이션 이런걸로 설명해주고 이런걸 원한건데 외부 캐릭터도 있고 근데 이건 오픈월드라 하기에는 너무 아무것도 없는거같지 않나?"

**규모**
> "그냥 차라리 맵을 겁나 넓게 만들어서 10시간 이상 플레이해야 끝나게 만드는건 어떰? GTA마냥 컨텐츠를 겁나 많이 만들어"
> "참고로 현재 콘텐츠는 10분이면 끝남."

**교육**
> "이 게임에 교육적 목적이 많을 필요는 없지만 어느정도는 있어야해. 고등학교 1학년 과학 수준을 …"

**스토리 (사용자 원안 — 이게 정답 기준)**
> "스토리 완전 다시 만들자. … 이 뒤에 나오는 모든 내용은 그림 / 애니메이션 으로만 표현해야해. 글이 있으면 읽기 싫으니까. 있어도 간략하게만. 맨 처음에 사과모양행성을 보고 반해서 주인공이 사과모양행성을 사고 싶어하는 씬이 딱 보이면서 그게 행성을 훔치는 동기가 되는거야. 그래서 행성을 훔쳐서 암시장에 갖다 파는데 어떤 수호신이 사는사람인척 훔치는놈(나)를 딱 보게 되는거지. 그 뒤로 수호신이 맵 곳곳에 숨어있고 내가 쳐다보면 숨고 하다가 내가 마지막 한탕 그니까 겁나 희귀한 행성 3개인데 붙어있음.(삼성) 을 찾게되어서 그걸 훔치려다가 뒤에서 참다참다하는 수호신이 쫓아오고 나는 기지까지 도망치면 그게 산거임. 그리고 그걸 암시장에 팔고 이제 사과모양행성을 찾으러가다가 의뢰가 하나 들어와서 다른 행성 잡으러 가는길에 누가 칼을 탁 쳐서 그게 날라가서 지가 사고싶었던 사과모양행성에 날라가서 우울해하는게 엔딩이야. 엔딩 다음에는 자유롭게 돌아다니거나 평소처럼 훔치거나 집을 사거나 가능함."

**작업 방식**
- "스토리 문서/콘텐츠는 docs에 따로 정리" / "교육 내용은 따로 docs에 뭘 배우는지 정리" / "추상적이니까 docs에 다른 파일로 정리해서 방향을 잡을 수 있도록"
- "CSS, TS 둘 다 500줄 제한. 다 깔끔해야 함. HTML은 동적 로딩할 거니까 상관없음"
- "typescript + cpp 서버 구조로 리팩터링", "에이전트 적극 활용 가능", "커밋은 하고(진행)"
- `previous/` 삭제와 `.gitignore`의 `CLAUDE.md` 추가는 **사용자가 직접 한 변경**이다(건드리지 말 것).

### 2.2 스토리 v2 요약 (사용자 원안 기준)
`사과 모양 행성에 반함(동기) → 행성을 훔쳐 암시장에 팖 → 사람인 척한 수호신에게 들킴 → 수호신들이 맵에 숨어 있고, 쳐다보면 숨음 → 마지막 한탕: 희귀 행성 3개가 붙은 삼성 → 훔치려다 참던 수호신이 쫓아옴, 기지까지 도망 = 성공 → 암시장에 팔고 사과 행성 사러 감 → 의뢰가 들어와 다른 행성 잡으러 가는 길에 누가 친 칼이 날아가 사과 행성에 꽂힘 → 우울한 엔딩 → 엔딩 후 자유 플레이(돌아다니기·훔치기·집 구매)`
- **모든 연출은 그림/애니메이션**. 글은 퀴즈·상점 품목명·도감 정도만, 그것도 짧게.

### 2.3 대화 중 합의된 방향 (사용자가 동의/지시한 것)
- 월드는 **섹터(우주 구역) 여러 개 + 허브(기지)** 구조로 확장, 구역마다 새 메커니즘·환경.
- 훔치는 동기 = 사과 행성(위 원안). 이전 안("지구 에너지 위기", 12막, 엔딩 3분기)은 **폐기**.
- 교육은 "어느 정도": 퀴즈가 교육 담당, 우주 소재에 얹기, 해설 짧게.
- 목표 시간 10시간+ (현재 10분).

## 7. 협업·구현 시 주의

- **레지스트리로 붙이기**: 새 시스템은 파일을 만들고 `client/src/systems/index.ts`에 import + register **한 줄**. `id` 중복은 throw. 호출 순서 = 등록 순서. 자세한 시그니처와 레시피는 CLIENT.md.
- **세이브 호환**: 행성 id·섹터 id는 **세이브 키**이므로 바꾸지 말 것. 기존 행성 id 0~24 고정, 신규는 뒤에 추가. 새 필드는 `core/save-schema.ts` 마이그레이션 체인(`STEPS[v]`)으로. PUT 상한 256KB.
- **무문자 위반 금지**: 스토리·튜토리얼·HUD에 `textContent`로 문장을 넣지 말 것(퀴즈·상점·도감·시스템 오류만 예외).
- **병렬 에이전트 소유권**: 같은 파일을 동시에 수정하면 충돌한다. 공용 파일(`loop.ts`, `world.ts`, `types.ts`, `systems/index.ts`)은 마지막에 한 명이 통합.
- **검증은 직접**: 에이전트 보고를 그대로 믿지 말고 `tsc`, `wc -l`, E2E를 직접 돌릴 것. 이 프로젝트에서 보고와 실제가 어긋난 적이 있었다(예: 메시지를 엉뚱한 에이전트에게 보냄).
- **실측 우선**: 경제 수치는 시뮬만으로 확정하지 말고 사용자 플레이 시간으로 보정.
- **한국어로 소통**, 파일 참조는 `경로:줄` 형식.
